# DATA:EZ 합성 PG 샘플

실제 PG사에서 받은 파일이라고 가정한 **가상 자료**입니다. 실제 고객·가맹점 정보는 없으며 특정 PG사의 공식 내보내기 형식을 재현한 것은 아닙니다. 가상 예약 매장의 2026년 8월 31일~9월 8일 결제·취소를 담았습니다. 금액은 원화, 시간은 한국 시간입니다. 수수료 3%와 정산 예정일은 예시 규칙입니다.

## 빠른 시작

1. `합성 강남점` 가게를 만들고 아래 매핑으로 `가상PG 결제` 출처를 만듭니다.
2. `01_gangnam_pg.csv`를 미리보기 후 반영합니다. 엑셀을 쓰려면 저장소의 `outputs/01a07df0-dba6-7841-8cde-f4505b7e6614/DATAEZ_가상PG_강남.xlsx`를 대신 선택합니다. 둘은 같은 40개 거래입니다.
3. 같은 출처에 `03_gangnam_pg_overlap.csv`를 반영합니다. 기존 12건은 건너뛰고 새 거래 14건만 추가되어 총 54건이 됩니다.
4. 별도 `현금 장부` 출처를 아래 현금 매핑으로 만듭니다. `08_cash_first.csv`를 반영한 뒤 `09_cash_review.csv`의 **파일 행 2는 제외, 행 3은 포함**하고 반영합니다. 파일 행 번호는 헤더를 포함하며, 행 3은 같은 금액의 별도 거래라고 가정한 정답입니다.
5. `합성 홍대점` 가게를 만들고 PG 출처에 `07_hongdae_pg.csv`를 반영합니다. 강남과 거래번호가 겹쳐도 가게·출처가 다르므로 별도 거래입니다.
6. 챗봇에 “가상PG 결제와 현금 장부의 이번 달 순결제액을 합친 지표를 미리 보여줘”라고 입력합니다. **2026년 9월 실행 기준 1,386,000원**입니다. 저장을 요청하면 대시보드 지표로 추가할 수 있습니다.

CSV를 엑셀에서 열고 다시 저장하면 긴 숫자형 거래번호의 앞자리 0이나 정밀도가 손상될 수 있습니다. CSV는 DATA:EZ에 원본 그대로 올리세요. 제공된 XLSX는 거래번호를 문자 셀로 저장했으며 실제 저장 파일을 다시 읽어 검증했습니다.

## 출처 매핑

| 설정 | PG 파일 | 현금 파일 |
|---|---|---|
| 출처 이름 | 가상PG 결제 | 현금 장부 |
| 제공자 | 가상PG | 직접입력 |
| 계정 | 강남 000001001 / 홍대 000002001 | 가게별 현금 장부 |
| 피드 | 결제취소이벤트 | 현금기록 |
| 금액 | 거래금액 | 금액 |
| 발생 일시 | 거래일시 | 발생일시 |
| 이벤트 ID | 거래번호 | 연결하지 않음 |
| 원거래 ID | 원거래번호 | 연결하지 않음 |
| 통화 컬럼 | 통화 | 연결하지 않음, 기본 KRW |
| 금액 방식 | 부호 유지(signed) | 부호 유지(signed) |
| 시간대 | Asia/Seoul | Asia/Seoul |

양수는 승인, 음수는 취소입니다. `거래구분` 문구 대신 부호로 이벤트 종류를 결정합니다. 하나의 원거래에 서로 다른 부분 취소 ID가 있으면 각각 보존합니다. 이미 음수인 취소 금액을 다시 차감하면 안 됩니다.

기본 관리 원장은 이벤트 ID·원거래 ID·종류·금액·발생 일시·통화의 6개 필드입니다. G부터 새 출처 등록의 추가 정보에 `결제수단`, `판매채널`, `PG수수료`를 연결하면 각각 payment_method, channel, fee로 보존합니다. 기존 E/F 재현용 manifest의 기본 매핑은 유지했습니다. 이미 기본 매핑으로 등록했다면 [H의 과거 속성 복원](../../docs/ATTRIBUTE_RESTORATION.md)으로 원본 검사 후 선택 속성을 추가할 수 있습니다. [G 사용 안내](../../docs/PAYMENT_ATTRIBUTES.md)에 분석 예시와 정답을 정리했습니다. `정산 참고자료`는 일반 테이블로 올리고 결제 매출과 합산하지 마세요.

## 검증 재실행

저장소 루트에서 API Python 의존성이 설치된 환경을 사용합니다. PostgreSQL은 로컬의 **테스트 서버**여야 하며 CREATE DATABASE 권한이 필요합니다. 스크립트는 매번 임의 이름의 DB를 생성하고 종료 시 삭제합니다. 실제 앱 데이터에는 샘플이 남지 않습니다.

```powershell
$env:DATAEZ_TEST_DATABASE_URL='postgresql://dataez_test@127.0.0.1:55439/postgres'
python scripts/pg-eval/run.py
python scripts/pg-eval/run.py --live-llm
```

두 번째 명령은 `.env` 또는 환경변수의 모델과 API 키로 실제 유료 호출을 합니다. 상대 기간 질문은 2026년 9월 기준이므로 다른 달에는 샘플·정답·질문 날짜를 함께 갱신해야 합니다. `--cases 15,16,17`로 일부만 재평가할 수 있습니다. RAG 임베딩 검색은 이 임시 환경의 pgvector 부재로 비활성화되며, 실제 모델의 도구 선택·SQL 집계·지표 저장·업로드 이력 설명을 평가합니다. HTTP·브라우저·백그라운드 갱신은 기존 D단계 검증 범위입니다.

결과는 `scripts/pg-eval/artifacts/<run-id>/report.json`, 문항별 전체 질문·답변·도구 인자·도구 결과는 `case-XX.json`에 남습니다. 로그에는 합성 자료만 들어가며 API 키는 출력하지 않습니다. 자동 검사 결과와 답변 의미 검토를 분리합니다. 비용은 프로젝트 요율표의 추정치로 실제 청구액이 아닙니다.
