## 1. 합의한 제품 방향

- 첫 사용 튜토리얼을 확장하기 전에 핵심 화면 구조와 사용 흐름을 개선한다.
- 자연어로 통계와 그래프를 만드는 작업을 중심에 둔다.
- 중앙에는 그래프 미리보기와 대시보드 작업 공간을 배치한다.
- 채팅은 오른쪽에서 접고 펼칠 수 있게 한다. 닫아도 중앙의 작업 결과는 유지한다.
- 사용자가 올린 원본 파일을 보관하고 다시 분석에 사용하는 파일 보관함을 제공한다.
- 한 계정의 여러 가게를 지원하며, 분석에 포함하는 가게와 파일을 명확히 보여준다.
- 실제 서비스 일정은 없으며 데모에서 사용할 수 있는 범위로 구현한다. 실제 PG 파일과 외부 PG 연동은 계속 보류한다.
- Supabase Storage를 원본 보관의 우선 연결 대상으로 검토한다. 이번 기록 단계에서는 원격 프로젝트나 버킷을 생성하지 않았다.
- 다크를 기본으로 두고 라이트도 함께 지원한다. 2026-09-09 사용자가 차콜 + 블루 팔레트를 확정했고 시안 공통 토큰에 반영했다.

## 2. 메뉴와 화면 구성안

사용자와 논의한 방향을 구체화한 구성안이다. 상세 배치와 기본 열림 상태는 시안에서 확인한다.

| 위치 | 구성 | 역할 |
|---|---|---|
| 왼쪽 상단 | 가게 선택·추가 | 현재 작업할 가게 선택 |
| 왼쪽 주요 버튼 | 새 분석 | 새 대화를 시작하고 오른쪽 채팅 열기 |
| 왼쪽 메뉴 | 대시보드 | 저장한 그래프 확인·배치 편집 |
| 왼쪽 메뉴 | 데이터 관리 | 파일 보관함과 분석 장부 탭 제공 |
| 왼쪽 메뉴 | 분석 기록 | 현재 가게의 이전 대화와 결과를 다시 열기 |
| 왼쪽 하단 | 설정·내 계정 | 가게 정보, 계정 정보와 로그아웃 |
| 중앙 | 작업 공간 | 분석 결과 미리보기, 저장한 그래프, 선택한 파일·장부 표시 |
| 오른쪽 | 접고 펼치는 채팅 | 질문, 후속 수정, 파일 선택, 작업 상태 표시 |

분석 기록을 열면 대화와 해당 결과를 함께 표시한다. 저장 전 미리보기와 저장된 지표를 구분하고, 저장·수정은 사용자의 명시적인 요청이나 버튼 동작에 따른다. 채팅 패널을 닫는 동작 자체로 분석을 저장·삭제·취소하지 않는다.

여러 가게 비교는 분석 대상 선택으로 제공한다. 현재 작업 가게와 실제 집계에 포함된 가게들은 각각 표시한다. 현금 입력은 데이터 관리의 주요 작업으로 유지한다. SQL, 상세 계산식과 갱신 설정은 선택한 지표의 상세 보기에 둔다.

## 3. 파일 보관함 범위

| 기능 | 제안 동작 |
|---|---|
| 원본 보관 | 가게별로 업로드한 원본 파일을 보관 |
| 목록·검색 | 파일 이름, 종류, 크기, 업로드 시각, 처리 상태 표시 및 파일명 검색 |
| 미리보기·다운로드 | 지원 형식의 미리보기와 원본 다운로드 |
| 분석 연결 | 파일의 '이 파일로 분석' 동작으로 오른쪽 채팅과 연결 |
| 채팅에서 재사용 | 첨부 메뉴의 '내 기기에서 업로드' / '보관함에서 선택' 지원. 계정 소유 파일을 검색하고 가게·파일 종류·준비 상태를 확인해 선택 |
| 자연어로 파일 찾기 | '지난달 성수점 카드 매출 파일로 분석해줘'처럼 요청하면 권한 범위 안에서 파일 후보를 찾고, 모호하면 후보를 제시 |
| 상태 안내 | 보관 중, 검토 필요, 분석 가능 등 실제 처리 상태 표시 |
| 연결 정보 | 원본 파일이 어느 장부와 지표에 사용되는지 확인 |

대표 흐름은 `파일 보관 → 컬럼·중복 검토 → 분석 장부 반영 → 자연어 질문 → 그래프 미리보기 → 대시보드 저장`이다. 파일 보관만 원하는 사용자도 지원한다. 통계 계산은 검사·반영이 완료된 데이터로 실행하며, 참고 문서 검색의 준비 상태는 별도로 다룬다.

파일 보관과 거래 반영을 별도 상태로 관리한다. 파일 재선택이나 채팅 재사용으로 같은 거래가 다시 반영되지 않도록 기존 중복 검토를 재사용한다.

2026-09-09 추가 요구: AI 채팅에서 **사용자 계정의 저장소에 보관된 파일을 직접 불러오는 기능**을 필수 범위로 확정한다. 기본 목록은 현재 가게이며, 계정 전체 파일도 가게 표시와 함께 탐색할 수 있게 한다. 다른 가게 파일 선택이 현재 작업 가게 변경이나 거래 재반영으로 이어지지 않도록 실제 분석 범위를 별도로 표시한다. 파일 선택과 자연어 검색 모두 같은 소유권·가게·준비 상태 검사를 거친다. [채팅 연결 상세 요구사항](FILE_LIBRARY_CHAT.md).

보관함 원본은 현재의 미반영 업로드 24시간 만료 정책과 분리한다. 파일 삭제와 장부 데이터 삭제의 영향도 분리한다. 구체적인 삭제·보관 정책은 구현 전에 확정한다.

## 4. 기존 구현과 연결할 부분

- `api/app/storage.py`: 로컬 디스크·S3 저장 및 업로드 검토용 임시 저장 기능이 있다. Supabase S3 연결에 필요한 endpoint와 자격 증명 설정 등을 확장할 수 있다.
- `api/app/main.py`: 파일 업로드와 사용자별 파일 목록 API가 있다. 파일 보관함에는 가게 소유권·연결 상태·다운로드·분석 재사용 API 보완이 필요하다.
- `api/app/ledger_imports.py`: 파일 검사, 중복 검토, 거래 반영과 임시 파일 만료를 처리한다. 영구 보관한 원본을 이 흐름에 연결해야 한다.
- 기존 대화·위젯·레이아웃 저장 API를 재사용한다. 채팅과 중앙 결과를 동시에 표시하려면 대화 선택, 실행 상태, 미리보기와 입력을 가게별 작업 공간의 공통 상태로 연결했다. 저장 상태·중복 저장 방지·저장 위젯 이동은 Phase 4에서 연결했다.
- 상단의 고정 '최근 30일'과 미연결 검색·알림 버튼을 제거하고, 현재 작업 가게·테마·채팅 버튼을 연결했다.

원본 파일은 Supabase Storage의 비공개 버킷에 보관하고, 파일 메타데이터와 가게·장부 관계는 현재 애플리케이션 DB에서 관리하는 구성을 우선 제안한다. 현재 로그인 체계를 사용해 서버에서 소유권을 확인한 뒤 파일을 읽거나 다운로드 URL을 발급한다. 서버용 S3 키는 RLS를 우회하므로 서버의 소유권 확인을 생략할 수 없으며 브라우저에 전달하지 않는다.

Supabase가 제공하는 S3 호환 기능을 활용하되 파일 보관함의 상태·장부 연결·삭제 정책은 DATA:EZ가 구현해야 한다. 파일 버전이나 휴지통은 아직 범위에 넣지 않았다.

공식 참고 문서:

- [Storage 버킷과 비공개 접근](https://supabase.com/docs/guides/storage/buckets/fundamentals)
- [S3 호환 범위](https://supabase.com/docs/guides/storage/s3/compatibility)
- [S3 인증과 서버용 키](https://supabase.com/docs/guides/storage/s3/authentication)

## 5. 아직 결정하지 않은 선택

- 사용자가 제공한 OpenAI Platform 화면을 바탕으로 차콜 다크를 기본으로 한다. 차콜 + 블루 A안으로 확정했으며 두 테마를 지원하는 시안에 반영했다. 실제 앱에도 적용했다.
- 글자 크기·간격의 최종 조정. 기본 글꼴은 **Spoqa Han Sans Neo로 확정**하고 시안·실제 앱에 적용했다. [글꼴 비교실](../outputs/frontend-design/typography.html)에서 크기와 간격을 조절할 수 있다. [선택 결과와 검증](TYPOGRAPHY.md)을 참고한다.
- PC·모바일에서 지원할 제작·편집 기능의 범위.
- 패널 너비 직접 조절 방식. 현재 기본 진입은 닫힘이며 새 분석 또는 채팅 버튼으로 연다. 1100px 이하에서는 모바일 모달로 연다.
- 대시보드를 항상 이동 가능하게 할지, 별도 배치 편집 모드를 제공할지.
- 보관함의 초기 지원 파일 형식, 폴더·태그 필요 여부, 용량·보관·삭제 정책.
- Supabase 원격 프로젝트 연결 또는 로컬 개발 환경의 구체적인 설정.

계정 전체 가게 요약, 여러 개의 이름 있는 대시보드, 모든 지표에 적용하는 공통 기간 필터는 이번 합의에 포함되지 않았다. 추가할 경우 데이터 의미와 저장 방식을 별도로 설계한다.

## 6. 구현 순서 제안

| 단계 | 작업 | 확인할 결과 |
|---|---|---|
| 1. 화면 시안 | 중앙 작업 공간·오른쪽 채팅·파일 보관함 배치 | 주요 화면과 이동 흐름을 보고 상세 선택 확정 |
| 2. 공통 화면 구조 · 완료 | 내비게이션, 가게 선택, 채팅 접기·펼치기, 중앙 결과 연결, 테마 토큰 | [검증 기록](WORKSPACE_FOUNDATION.md) |
| 3. 파일 보관함 · 기본 연결 완료 | 저장소 연결, 원본 목록·다운로드·상태, 기존 장부 반영·채팅 재사용 | 재업로드 없이 파일을 찾아 분석하고 기존 중복 검토 유지 |
| 4. 화면 완성·검증 · 완료 | 대시보드 편집, 읽기 쉬운 지표 카드, 오류·빈 화면·로딩, 접근성 | 파일 보관부터 첫 그래프 저장·재접속까지 실제 브라우저로 확인 |

검증에는 다른 사용자·가게 파일 접근 차단, 임시 파일 만료 후 보관 원본 유지, 실패 후 재시도, 채팅 중 가게 전환, 저장 지표의 배치·갱신 주기 유지가 포함된다. 실제 사용자 사용성 점검은 구현 검증 뒤에 진행한다.

## 7. OpenAI Platform 참고 시안과 엔진 검토

사용자가 제공한 `https://platform.openai.com/home` 화면을 참고해 차콜 배경, 얇은 경계선, 간결한 내비게이션과 구분선으로 나눈 요약 지표를 적용했다. [실행 가능한 시안](../outputs/frontend-design/index.html)과 [동작·검증 범위](../outputs/frontend-design/README.md)를 별도로 제공한다. 실제 앱 연결 전에 화면과 상호작용을 확인하기 위한 단계다.

시안은 Apache ECharts 6.0.0 SVG 렌더러를 사용한다. 실제 앱은 Phase 4에서 ECharts 6.1.0으로 전환했다. 사용자가 추가로 소개한 vgpu는 통계 차트 외에 소개 화면·빈 작업 공간의 GPU 시각 효과 후보로 검토했다. 현재 시안에 vgpu를 설치하거나 연결하지 않았다.

사용자가 ECharts 시안에 긍정적인 의견을 주었고, 다크 기본·라이트 고려 방향을 추가했다. [확정 차콜 + 블루 팔레트](COLOR_PALETTE.md)을 만들어 시안에 다크·라이트·시스템 선택을 연결했다. [팔레트 비교 화면](../outputs/frontend-design/palette.html)에서 두 테마를 확인할 수 있다. 2026-09-09 사용자가 차콜 + 블루를 최종 확정했으며 시안에 반영했다. 실제 앱 프론트엔드의 색상·테마와 공통 작업 공간 통합을 완료했다.

## 8. 현재 남은 작업

1. ECharts 실제 통합과 분석 결과·대시보드 개선을 완료했다. [결과·검증 범위](ANALYSIS_DASHBOARD_UI.md). 후속 화면 조정은 실제 사용자 사용성 점검을 바탕으로 진행한다.
2. 파일 보관함과 채팅 연결을 구현했다. [구현 범위](FILE_LIBRARY_CHAT.md). 원격 Supabase 연결, 원본 행만 분석하는 범위, 보관 정책·폴더/태그는 후속 작업이다.
3. 파일 선택 → 자연어 질문 → 저장 → 갱신 → 재접속의 [실제 API·DB·LLM 통합 검증](WORKSPACE_LIVE_ACCEPTANCE.md)을 완료했다. 모바일 상세 폼·첫 사용 안내와 더 다양한 실제 사용자 질문은 후속 범위다.
