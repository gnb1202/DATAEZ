# 보관함 파일을 AI 채팅에 연결

> 2026-09-10 후속 구현: [파일 원본·누적 장부 범위, 저장 전 설정, 샘플 첫 사용 안내](FILE_SCOPE_AND_FIRST_USE.md). 아래의 이전 단계 기록보다 이 문서의 최신 동작을 우선합니다.

2026-09-09 · 보관함 및 AI 채팅 연결 구현. 로컬 원본 저장소에서 검증했으며 Supabase 원격 연결 검증은 별도다.

## 사용자 흐름

1. 채팅 첨부 메뉴에서 `내 기기에서 업로드` 또는 `보관함에서 선택`을 고른다.
2. 보관함은 현재 가게의 파일을 기본 표시한다. `내 계정 전체` 범위에서 다른 운영 가게와 미분류 파일도 검색할 수 있다. 파일명·가게·종류·업로드 날짜·준비 상태로 파일을 구분한다.
3. 파일 하나 또는 여러 개를 선택하면 입력창 위에 파일명과 연결된 가게를 표시한다. 선택을 해제해도 원본이나 장부를 삭제하지 않는다.
4. 질문을 전송하면 선택한 파일과 연결된 분석 장부/문서를 참조한다. 결과에는 사용한 파일·가게·집계 기간을 표시하고 출처를 다시 열 수 있게 한다.
5. `지난달 성수점 카드 매출 파일 찾아줘`처럼 자연어로도 보관함을 탐색한다. 같은 이름·기간의 후보가 여럿이면 후보를 보여주며, 임의의 파일로 확정하지 않는다.

## 데이터 의미와 가게 범위

- 파일을 보관함에서 고르거나 다시 질문하는 동작 자체로 재업로드·거래 중복 반영·장부 생성이 발생하지 않는다.
- 이미 장부에 반영된 파일은 기존 연결을 재사용한다. 아직 반영되지 않은 CSV/엑셀은 컬럼·중복 검토와 장부 반영으로 안내한다. 문서 검색 준비 상태는 거래 반영 상태와 구분한다.
- 계정 소유권과 분석 범위는 별개다. 현재 가게 외 파일은 소속 가게를 명시하고, 여러 가게 분석 대상이 확정된 경우에만 함께 집계한다. 선택만으로 현재 작업 가게나 파일 소속을 바꾸지 않는다. 미분류 파일은 반영할 가게를 지정한다.
- 파일을 명시적으로 선택한 질문은 그 파일의 연결 장부·문서를 우선 분석 대상으로 삼는다. 범위가 부족할 때 계정 전체 자료를 묵시적으로 포함하지 않는다.
- 원본 파일 단위와 전체 장부 단위를 구분한다. 예를 들어 8월 파일이 1년치 장부에 누적 반영되었다면 파일 선택만으로 전체 장부 합계를 그 파일의 합계로 표시하지 않는다. 배치·행 출처로 계산 범위를 좁히거나 전체 장부 기준임을 안내하고 범위를 확정한다.
- 채팅 닫기·메뉴 이동 때 선택 파일을 유지한다. 가게 변경은 현재 공통 작업 공간 정책에 따라 미전송 선택을 초기화한다. 저장된 대화는 당시 참조 파일을 기록해 재접속 시 출처를 다시 확인할 수 있게 한다.
- 삭제·만료·권한 변경으로 원본을 열 수 없으면 이력에서 상태를 표시한다. 이름이 같은 다른 파일로 대체하지 않는다.

## 구현

- 데이터 관리에 `분석 장부 / 파일 보관함` 보기를 추가했다. 채팅에는 기기 첨부와 `보관함에서 선택` 두 경로가 있다. 기기 첨부와 보관 파일 선택을 한 질문에서 혼합하지 않으며, 새 파일을 먼저 보관하면 기존 파일과 함께 선택할 수 있다.
- 현재 가게 기본 목록, 내 계정 전체, 파일명 검색, 종류 필터, 30개 단위 목록, 미리보기·원본 다운로드·가게 미지정 보관을 지원한다. 분석에는 최대 10개 파일을 선택한다.
- 파일 보관 자체는 장부를 생성하지 않는다. CSV/Excel은 기존 전체 파일 검사·정밀 숫자 파서를 거쳐 `검사한 파일을 분석에 연결`할 때 장부를 한 번 생성한다. PDF/MD/TXT는 기존 문서 색인 작업을 등록하며, 성공 상태가 되어야 선택할 수 있다. 실패 상태는 표시하고 기존 검색 갱신 화면에서 재시도한다.
- 이미 장부로 가져온 파일과 확정된 결제 반영 배치의 원본은 같은 보관함에서 기존 장부 연결로 보인다. 파일 행 하나에 여러 연결이 있는 경우 하나를 명시적으로 선택한다.
- 이번 집계 기준은 **연결된 장부 전체**다. 원본 파일 행만 집계하는 기능은 아니다. 선택기에서 이를 확인하며, 다른 가게를 고르면 해당 가게 포함도 확인한다. 기간은 질문과 실제 날짜 컬럼으로 결정한다.
- 파일 ID·연결 장부 ID만 채팅 API로 전달한다. 서버에서 계정 소유권, 가게 연결, 제거 여부, 문서 준비 상태와 범위 확인을 다시 검사한다. 보관함 선택으로 원본 바이트를 첨부 import 경로에 넣지 않는다.
- `search_library_files`는 같은 소유권·검색 필터로 후보를 반환한다. LLM이 자동으로 파일을 확정하거나 재반영하지 않으며, 응답의 후보에서 선택기를 열 수 있다. 큰 후보 목록도 구조화된 형태로 이력에 보존한다.
- 명시적 파일 선택 시 SQL의 장부 조회 목록과 문서 검색의 `file_ids`를 제한한다. 다른 가게의 선택 장부도 별도 이름으로 조회하며, 선택하지 않은 장부와 금융 원본 변경 도구는 차단한다. 저장 지표는 기존 가게별/v5 정의 조건을 따른다. 다른 가게의 일반 CSV 조회 차트와 갱신 가능한 다가게 결제 지표는 구분한다.
- 사용자·AI 메시지의 `library_references` 단계에 파일 ID·이름·해시(신규 보관 파일)·장부·가게·범위를 기록한다. 기존 가져오기 파일은 해시가 없을 수 있다. 채팅 닫기·화면 이동 시 선택을 유지하고, 가게 변경 시 초기화한다. 이력 복원 시 선택을 다시 불러오며 전송 시 재검사한다.
- 제거된 파일은 동일 이름 파일로 대체하지 않는다. 전송 전 검사 실패 시 질문 초안을 유지한다. 원본이 없으면 미리보기/다운로드/연결 API가 410을 반환한다. 이미 연결된 장부 분석은 장부 데이터와 연결 상태를 기준으로 한다.
- `보관함에서 제외`는 목록에서 숨기는 동작이다. 원본·장부·이력은 물리적으로 삭제하지 않는다. 폴더, 태그, 용량 할당, 원본 물리 삭제 및 보존 기간 설정은 후속 범위다.

## API와 저장소

| 경로 | 기능 |
| --- | --- |
| `GET /api/library/files` | 가게·파일명·종류·페이지별 소유 파일 조회 |
| `POST /api/library/files` | 원본 보관, 같은 가게의 동일 내용 재업로드 재사용 |
| `GET /api/library/files/{id}` | 상태·연결 확인 |
| `GET /api/library/files/{id}/preview` | 앞 8행 또는 문서 텍스트 앞부분 |
| `GET /api/library/files/{id}/download` | 인증된 원본 다운로드 |
| `POST /api/library/files/{id}/prepare` | 파일 검사 후 장부 또는 문서 색인 연결 |
| `POST /api/library/files/resolve` | 전송 전 선택 유효성 검사 |
| `DELETE /api/library/files/{id}` | 보관함에서 제외 |

`library_entries`는 기존 `files`와 연결되며 `010_file_library.sql` 및 API 시작 시 초기화한다. 서버 소유 DB 역할로 접근하고, 브라우저에 DB/저장소 관리자 키를 제공하지 않는다. 신규 테이블은 RLS를 켜고 PUBLIC 권한을 제거했다. 파일 보관과 연결에 트랜잭션 잠금을 사용해 동시 업로드·동시 준비 요청을 직렬화한다. 가게가 최종 삭제되어도 원본 파일은 미지정 보관함으로 남는다. 미지정 파일 중복은 계정·해시 잠금으로 제어하며, 가게 연결 시 기존 동일 해시가 있으면 409로 안내한다.

기본은 기존 `STORAGE_BACKEND=local`과 `LOCAL_STORAGE_PATH`다. Supabase Storage의 S3 호환 API를 위한 서버 설정도 추가했다:

```dotenv
STORAGE_BACKEND=s3
S3_BUCKET=<비공개 버킷 이름>
S3_ENDPOINT_URL=https://<project-ref>.storage.supabase.co/storage/v1/s3
AWS_REGION=<프로젝트의 S3 설정에 표시된 리전>
S3_ACCESS_KEY_ID=<서버 전용 S3 키 ID>
S3_SECRET_ACCESS_KEY=<서버 전용 S3 비밀 키>
```

서버 어댑터는 SigV4와 path-style을 사용한다. S3 키는 RLS를 우회하는 권한이 있으므로 Next.js 공개 환경 변수에 넣지 않으며, 현재 API 소유권 검사를 통과한 요청만 저장소로 보낸다. 비공개 버킷 생성·실제 업로드 및 다운로드 확인은 Supabase 프로젝트가 연결된 후 수행한다. [공식 S3 인증 문서](https://supabase.com/docs/guides/storage/s3/authentication), [지원 API](https://supabase.com/docs/guides/storage/s3/compatibility).

문서 검색에는 기존 pgvector, `RAG_ENABLED`, 색인 워커 및 임베딩 설정이 필요하다. 이번 실제 모델 검증은 CSV 탐색·SQL 분석이며 PDF 검색 품질이나 Supabase 원격 저장을 검증한 것은 아니다.

## 완료 조건

- 업로드해 보관한 파일을 재접속 후 채팅에서 찾아 선택하고 결과를 만든다.
- 같은 파일을 반복 선택해도 파일·거래 행이 추가되지 않는다.
- 현재 가게·계정 전체 목록, 다른 가게 비교, 미분류 파일의 연결 범위가 구분된다.
- 다른 사용자의 파일 ID나 허용하지 않은 가게 범위를 API에 직접 보내도 읽기·분석이 차단된다.
- 같은 이름의 파일, 준비 중·검토 필요·삭제된 파일을 구분하고 필요한 다음 동작을 표시한다.
- 선택한 파일보다 넓은 장부를 집계할 때 이를 파일 단위 결과로 오인시키지 않는다.
- 채팅 닫기와 모바일 패널 전환 후 선택 유지, 가게 전환 초기화, 대화 이력 출처 복원을 검증한다.

이 작업은 원본 파일 보관함 페이즈의 필수 범위이며 ECharts 교체와 별개다.
