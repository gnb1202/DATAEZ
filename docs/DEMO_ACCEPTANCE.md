# Phase 1 — 지속형 데모 점검

2026-09-10. `codex/demo-environment`에서 웹·API·PostgreSQL로 지속형 로컬 데모를 구성했다. Redis 제거 커밋 `9ca8949` 위의 후속 작업이다. 외부 공개 배포와 실제 사용자 관찰은 수행하지 않았다.

실DB 검사는 별도 일회용 PostgreSQL의 테스트 스키마를 사용했다. 해당 테스트 컨테이너·익명 볼륨은 종료 후 제거했다. 지속형 데모의 데이터는 그대로 남겨 두었다.

## 실제 브라우저 점검 6개

1. 실제 계정 로그인과 예시 대시보드 준비. 반복 실행해도 예시 위젯은 3개다.
2. 샘플 시작 시 원본 파일을 선택하고 질문 초안을 채우며 자동으로 전송하지 않는다.
3. 실제 LLM이 원본 범위의 재계산 가능한 꺾은선 정의와 정확한 일별 금액을 반환한다. 화면에서 집계표와 실행 SQL을 확인한다.
4. 저장 설정·미리보기·저장·크기 조절을 실제 UI로 실행한다. API로 30,000원 거래를 추가하면 원본 합계는 **690,200원**, 누적 장부는 **720,200원**이다.
5. 브라우저를 닫고 웹·API·DB 모두를 `stop`한 뒤 `start --no-build`한다. 원본 SHA-256, 대화 내용, 지표 정의·계산 결과·배치를 이전 응답과 비교해 일치한다.
6. 재시작 확인 화면에서 취소하면 현재 샘플이 그대로다. 새 샘플 만들기는 빈 새 작업 공간으로 연결하고 이전 샘플의 지표·대화를 보존한다.

실DB 회귀에서는 동시에 같은 샘플을 준비하거나 재시작하는 요청, 지표 1개 저장 뒤 실패, 파일 준비 실패 뒤 재시도를 실행했다. 가게·파일·위젯의 중복 없이 이어졌고, 기존 일반 가게·파일·지표와 다른 계정의 샘플이 그대로 유지됐다. 다른 계정/일반 가게/이전 샘플을 현재 대상으로 가장한 재시작은 거부했다. 예시 재호출로 사용자가 변경한 제목·배치를 덮어쓰지 않는 것도 확인했다.

## 발견한 문제와 재실행

- 웹 standalone 서버가 Docker의 컨테이너 호스트 이름에만 바인딩돼 loopback 상태 확인이 실패했다. `HOSTNAME=0.0.0.0`과 IPv4 상태 확인 주소로 수정한 뒤 healthy를 확인했다.
- KPI가 원화 단위 없이 `690200`으로 표시돼, 저장 지표는 기존 정확한 숫자 포맷터를 사용해 **690,200원**으로 표시하도록 수정했다. 소수 금액을 JavaScript Number로 변환하지 않는다.
- 최초 브라우저 검사는 접힌 시작 안내 바깥 패널을 열지 않아 중단됐다. 이어진 검사는 화면 전환 직후 패널이 아직 없는 시점에 검사하던 대기 문제를 드러냈다. 테스트가 실제 패널 마운트를 기다린 뒤 순서대로 펼치도록 고쳤다. 제품 API·계산 오류로 집계하지 않는다.
- 초기 단계 성공 뒤 재접속 단계만 재실행했다. 첫 재접속에서는 저장된 세션으로 복원됐고, 이미 사용한 회전 토큰으로 재검사할 때는 실제 로그인 화면에서 다시 인증했다. 통과 여부는 데이터 지속성으로 판정하며 무제한 세션 유지로 표현하지 않는다.
- Windows 실DB 검사에서 `localhost` IPv6 연결 대기로 지연돼, 격리 테스트 DSN을 `127.0.0.1`로 바꿔 완료했다.
