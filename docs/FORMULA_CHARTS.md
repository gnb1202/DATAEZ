# 그룹별 계산식 그래프와 분석 근거

2026-09-08. K·L 다음 작업으로 자연어 → 파일/장부 탐색 → 지표 정의 → SQL 집계 → 그래프 저장 흐름을 확장했다.

## 지원 범위

- “전체 기간의 주별 순결제액에서 PG 수수료를 빼고 매시간 갱신하는 그래프로 저장해줘.”
- “방금 저장한 그래프를 월별 막대로 바꿔줘. 위치와 갱신 주기는 유지해줘.”
- “채널별 이번 달과 지난달 순결제액 증감률을 보여줘.”
- “일별 금액 취소율을 보여줘. 취소 거래가 없는 날은 0으로, 승인 거래가 없는 날의 비율은 계산 불가로 남겨줘.”

두 항목의 차이·비율·증감률을 일·주·월 또는 문자 분류별로 계산한다. 같은 가게의 한 장부 또는 서로 다른 두 장부를 사용할 수 있다. 사용자와 가게 범위, 실제 컬럼, 숫자·날짜 타입을 기존 지표 서비스에서 검증한다.

채팅 미리보기의 **고정** 버튼도 재계산 가능한 지표를 저장한다. 저장된 그래프는 기존 수정·이력·복원, 수동/매시간/24시간 갱신, 드래그·리사이징 흐름을 사용한다. 정의를 수정해도 위젯 ID·배치·갱신 주기가 유지된다. 복원은 과거 정의를 현재 데이터로 다시 계산한다.

## 정의와 실행

기존 v1 단일 집계, v2 여러 장부 합계, v3 숫자 계산식은 유지한다. 새 `version=4`는 다음 구조다.

```json
{
  "version": 4,
  "operation": "difference",
  "dimension_label": "주",
  "chart_type": "line",
  "missing_group": "undefined",
  "left": {
    "label": "순결제액",
    "unit": "KRW",
    "definition": {
      "table_id": "실제 장부 UUID",
      "operation": "sum",
      "column": "amount",
      "group_by": "occurred_at",
      "date_grain": "week",
      "time_range": "all"
    }
  },
  "right": {
    "label": "PG 수수료",
    "unit": "KRW",
    "definition": {
      "table_id": "실제 장부 UUID",
      "operation": "sum",
      "column": "fee",
      "group_by": "occurred_at",
      "date_grain": "week",
      "time_range": "all"
    }
  }
}
```

위 예시의 UUID는 설명용이며 실제 요청에는 확인된 장부 ID를 넣는다. 자연어 도구는 확인한 `table_name`을 받아 현재 가게의 ID로 해석한다.

1. LLM이 출처와 컬럼을 확인한 뒤 구조화된 지표 정의를 만든다.
2. 서버가 정의를 검증하고 각 항목의 그룹 집계를 SQL로 생성한다. 식별자는 인용하고 조건값은 매개변수로 전달한다.
3. 단일 SQL 스냅샷에서 각 장부를 먼저 집계하고 `UNION ALL`과 `GROUP BY`로 같은 그룹을 맞춘다. 원본 거래 행끼리 결합하여 합계가 곱해지는 문제를 피한다.
4. 서버의 Decimal 계산기가 그룹별 차이·비율·증감률을 계산한다. 비율·증감률은 소수 네 자리, 동률은 짝수 쪽으로 반올림한다. 차이는 원래 소수 정밀도를 유지한다.
5. 정의, 결과, 집계 SQL 템플릿과 매개변수를 함께 저장한다. 자동 갱신에서는 LLM을 호출하지 않는다.

임의 Python/JavaScript 코드 실행이나 자유 수식 문자열 입력은 지원하지 않는다. SQL은 집계와 그룹 정렬을 담당하고 최종 두 값의 산술은 Decimal 계산기가 담당한다.

## 계산 규칙

| 조건 | 동작 |
|---|---|
| 날짜 그룹 | 한국 시간, 주는 월요일 시작. 양쪽 날짜 단위와 기간이 같아야 함 |
| 문자 그룹 | 실제 분류값을 그대로 맞춤. 각 항목은 서로 다른 기간 필터 사용 가능 |
| 한쪽에 거래 없음 | 기본 계산 불가. 명시한 `missing_group=zero`에서만 합계·건수를 0으로 계산 |
| 양쪽에 거래 없음 | 해당 날짜·분류를 새로 생성하지 않음 |
| 숫자 NULL | 빈 그룹과 구분하여 전체 계산을 거절. 임의로 0 또는 제외 처리하지 않음 |
| 분모 0 | 결과는 NULL, 그래프는 끊기며 집계표에 사유 표시 |
| 미제공 분류 | NULL 그룹으로 보존. 실제 문자열 “미제공”과 별개 |
| 1,000개 초과 그룹 | 일부만 저장하지 않고 범위 축소를 요청 |
| 새 데이터 또는 스키마 변경 | 저장한 출처·정의 재검증. 실패 시 직전 성공 결과와 실패 원인 유지 |

다른 기간의 날짜를 옮겨 맞추는 비교, 전월 동일까지의 비교, 이동평균·누적합·세 항목 이상 중첩 계산식, 여러 가게 비교는 이번 범위에 포함하지 않았다. 파일 반영·현금 입력 전의 외부 매출은 계산에 들어오지 않는다.

## 화면

채팅과 대시보드의 **집계표·SQL**에서 계산 기준, 원본 장부, 그룹별 두 집계값과 결과, 계산 불가/0 적용 사유를 확인한다. 표는 25개 그룹씩 보여준다. SQL은 고급 펼침 영역에서 최근 성공 계산의 템플릿과 매개변수를 분리해 표시한다. 이전 저장본에 SQL 기록이 없으면 재계산 안내를 표시한다.

금액은 API·저장·표·툴팁에서 소수 문자열을 유지한다. 그래프 좌표만 JavaScript 숫자를 사용한다. 위젯 차트는 변경한 높이에 맞춰 표시된다. 모델에 전달하는 큰 미리보기는 유효한 JSON과 명시된 5개 그룹 표본이며, 전체 결과와 SQL은 메시지와 차트에 보존된다.

## 검증과 실행

`api/tests/test_grouped_formula_metrics.py`는 실제 PostgreSQL로 계산·기간·누락·분모 0·정밀도·범위 격리·저장 이력·자동 갱신을 검증한다. `test_agent_history_context.py`는 큰 차트의 모델 문맥이 잘린 JSON이나 전체 결과로 오인되는 표본이 되지 않는지 검사한다.

```powershell
$env:DATAEZ_RAG_TEST_DATABASE_URL = 'postgresql://dataez_test@127.0.0.1:55440/postgres'
python -m pytest api/tests/test_grouped_formula_metrics.py api/tests/test_agent_history_context.py -q
python scripts/formula-charts-eval/run.py
```

실제 모델·브라우저 평가는 루프백의 격리 DB와 합성 PG CSV를 사용한다. API를 모킹하지 않으며 생성한 서버·DB를 정리하고 평가용 프론트 빌드를 일반 빌드로 복원한다. 원시 실행 결과는 Git에서 제외한 `scripts/formula-charts-eval/artifacts/`에 기록한다.

2026-09-08 검증 완료:

- 전체 API 테스트 **647개 통과, 건너뜀 0개**(165.37초). 이 중 이번에 추가한 그룹별 계산식 테스트는 20개, 큰 차트 문맥 테스트는 1개다.
- TypeScript 검사와 프로덕션 빌드 통과. 기존 ESLint 9 설정 호환 문제는 남아 있어 lint 통과로 보고하지 않는다.
- 실제 `gpt-5.4` / `gpt-5.4-nano`, `text-embedding-3-small`, Edge 브라우저로 세 자연어 시나리오를 검증했다. 주별 저장 → 크기 변경 → 월별 수정, 일별 취소율과 0분모, 미리보기 고정 및 재접속을 통과했다. 위젯 ID·배치·매시간 주기를 유지했다.
- 합성 거래 추가 후 기존 지표의 9월 차감액이 **281,300원 → 291,000원**으로 재계산됐다. API 평가의 9개 확인 항목이 모두 통과했고 브라우저 예외는 0건이다.
- 임시 평가 DB·프로세스를 정리하고 일반 프론트 빌드를 복원했다.
