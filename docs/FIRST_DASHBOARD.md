## 첫 사용 안내

대시보드 상단의 **첫 대시보드를 만들어보세요**에서 현재 가게의 준비 상태를 확인한다.

1. **가게 선택:** 가게가 없으면 첫 가게 생성 버튼을 제공한다. 생성 실패 시 입력을 유지하고 오류를 표시한다.
2. **파일 연결·반영:** 장부 관리로 이동하여 **파일로 출처 연결**을 누른다. 출처만 만들고 거래를 반영하지 않은 상태는 완료로 표시하지 않는다.
3. **첫 지표 저장:** 반영된 표준 결제·취소 장부 또는 현금 장부에서 출처를 선택한다. 일별 금액 그래프·전체 합계를 미리 보고 제목·기간·갱신 주기를 지정하여 저장한다.

진행 상태는 현재 가게의 출처·실제 행 수·재실행 가능한 저장 지표로 판단한다. 브라우저에 완료 플래그만 저장하지 않는다. 저장된 지표가 있으면 안내를 접어서 표시하며 다시 펼칠 수 있다. 다른 가게로 전환하면 그 가게의 상태로 다시 시작한다. 정적 차트만 있는 경우에는 재실행 지표 저장 완료로 판단하지 않는다.

일반 통계 파일과 과거 원본 형태로 전환한 장부는 기존 지표 만들기·AI 분석 경로를 유지한다. 첫 지표의 단축 설정은 금액·발생일이 표준화된 장부만 사용한다.

## 파일 연결

**파일 컬럼 확인**은 서버에서 실제 파일을 읽고 원본 컬럼, 전체 행 수, 앞 5행 표본을 반환한다. 표본 셀은 최대 160자다. 파일이나 출처를 저장하지 않는다.

- 원본 이름과 알려진 별칭이 하나만 일치하면 컬럼 후보로 연결한다.
- 승인금액·취소금액처럼 후보가 여러 개면 자동 선택하지 않는다.
- 금액의 의미는 이름으로 확정하지 않는다. 사용자가 결제만·취소만·부호를 유지하는 혼합 원장 중 하나를 선택한다.
- 일반적인 거래번호는 독립된 취소 ID인지 알 수 없어 자동으로 이벤트 ID에 연결하지 않는다.
- 통화 컬럼이 감지되면 연결을 요구하고 실제 값이 KRW인지 검사한다. 통화 컬럼이 없는 파일은 사용자가 원화 결제·취소 자료임을 확인한다.
- 정산 입금액과 집계표를 거래별 결제 원장으로 간주하지 않는다. 사용자가 자료의 의미를 확인해야 한다.

**연결한 파일 전체 검사**는 저장 없이 모든 행에 기존 결제 적재 검증을 적용한다. 금액·발생일·ID·통화·선택 속성을 검사하며, 표본 밖의 오류도 반환한다. 오류가 있으면 파일과 컬럼 선택을 유지하여 수정할 수 있다. 연결 규칙이 바뀌면 이전 검사 결과는 사용할 수 없고 다시 검사해야 한다.

검사 합계는 중복을 제거하기 전의 원본 금액이다. 화면에 이를 명시하고 이후의 최종 반영액과 구분한다. 금액은 Decimal로 계산하고 문자열로 전달하여 큰 금액의 소수를 보존한다.

지원 범위는 CSV·XLSX·XLS, 최대 20MB·100,000행·200컬럼이다. CSV는 기존 UTF-8/CP949/EUC-KR 읽기를 사용한다. Excel은 첫 번째 시트만 읽는다. 중복 헤더·빈 파일·수식/오류 셀 등은 기존 파일 검증과 추가 구조 검사에서 거절한다. 쉼표·통화 기호가 있는 금액과 모호한 날짜 형식은 자동 추측하지 않는다.

## 출처 저장·중복 검토·재개

검사를 통과하면 출처 이름, 파일 제공처, 가맹점·관리 계정을 지정한다. **출처 저장하고 중복 검토**는 기존 출처 등록·파일 업로드 API를 사용한다. 여기서 아직 거래를 장부에 반영하지 않는다.

같은 제공처·계정의 결제·취소 이벤트는 같은 출처로 관리한다. 이 안내의 자료 종류는 `결제·취소 이벤트`로 고정한다. 기존 장부 전환이나 별도의 자료 종류 설정은 기존 **새 출처 등록**에서 진행한다.

기존 업로드 검토 화면에서 **중복 검사·미리보기**를 실행하고 신규·중복·유사 후보·충돌·최종 반영 예정액을 확인한 뒤 **장부에 반영**한다. 미해결 후보·충돌을 자동 승인하지 않는다. 반영 완료 화면에서 대시보드로 바로 이동할 수 있다.

- 컬럼 확인·형식 검사 단계에서 새로고침하면 파일을 다시 선택해야 한다. 이 단계의 파일과 선택은 메모리에만 있다.
- 출처 저장 후 업로드가 실패하면 같은 출처·요청 키로 재시도한다. 출처와 파일의 기존 멱등성 처리를 재사용한다.
- 업로드 후에는 가게별 출처와 업로드 이력에서 검토·반영을 이어간다. 반영 응답을 잃은 경우에도 기존 배치 결과를 확인한다.
- 다른 가게로 전환하면 작성 중 파일 연결과 지표 설정은 해당 컴포넌트와 함께 초기화한다.

## 첫 지표와 자연어

첫 지표는 선택한 장부의 `amount`를 원본 부호대로 더하고, 일별 그래프는 `occurred_at`을 한국 시간의 날짜로 묶는다. 기본 기간은 파일 전체 기간, 갱신은 매시간이며 사용자가 변경할 수 있다. 취소를 포함하고 수수료를 자동 차감하지 않는다. 다른 장부·결제수단·가게의 거래는 자동으로 합산하지 않는다.

미리보기의 **집계표·SQL**에서 결과와 실행 근거를 확인한 뒤 **첫 지표 저장**을 누른다. 기존 지표 API·검증·주기 갱신·수정 이력·레이아웃 저장을 사용한다. 정상 주기 재계산에 LLM을 호출하지 않는다.

**이 출처로 자연어 질문 작성**은 선택 출처와 계산 기준을 담은 질문을 AI 분석 입력창에 넣는다. 자동 전송하지 않으며 사용자가 편집하고 전송한다. 대화와 메시지가 로드된 뒤 초안을 적용하여 입력이 사라지지 않도록 했다. 저장을 요청하지 않은 초안은 미리보기만 요청한다.

## API와 검증 재현

- `POST /api/projects/{project_id}/import-mapping/inspect`: multipart `file`, 읽기 전용.
- `POST /api/projects/{project_id}/import-mapping/validate`: multipart `file`, `mapping` JSON 문자열, 읽기 전용.

두 경로는 로그인과 가게 소유권을 확인하고 업로드 크기·요청 빈도를 제한한다. 소유권 확인용 DB 연결을 반환한 뒤 파일을 파싱한다. 미리보기 경로에서 파일 저장, 출처 생성, 거래 추가는 수행하지 않는다. 실제 반영에서 기존 서비스가 다시 파일과 출처를 검증한다.

```powershell
$env:DATAEZ_TEST_DATABASE_URL = 'postgresql://dataez_test@127.0.0.1:55439/postgres?connect_timeout=5'
$env:DATAEZ_RAG_TEST_DATABASE_URL = 'postgresql://dataez_test@127.0.0.1:55440/postgres?connect_timeout=5'
python -m pytest api/tests -q
python scripts/onboarding-eval/run.py
```

평가는 임시 계정·새 격리 DB·합성 CSV로 실제 API·Edge 브라우저·모델을 사용한다. 원시 계정 정보와 로그는 Git에서 제외한 `scripts/onboarding-eval/artifacts/`에만 보관한다. 검증 환경을 정리하고 일반 프론트 빌드를 복원한다.

2026-09-08 검증 결과:

- 전체 API **695개 통과, 건너뜀 0개**(219.58초). 이번 파일 검사 테스트는 16개다. 소유권 확인과 미리보기의 영속 데이터 미생성, 모호한 후보, 원본 ID, 표본 뒤쪽 오류, 통화, Excel 첫 시트, 정밀 소수 합계를 포함한다.
- 큰 정수와 아주 작은 소수가 함께 있는 합계의 정밀도 경계를 보완한 후 관련 **16개를 다시 통과**했다. TypeScript와 프로덕션 빌드도 통과했다. 기존 ESLint 9 설정 호환 문제는 남아 있으므로 lint 통과로 보고하지 않는다.
- 실제 Edge·API·모델을 사용한 첫 사용 평가가 통과했다. 평가 스크립트의 **12개 확인 항목 통과**, 브라우저 예외 0건이다.
- 합성 CSV **4행·180,000원**의 형식 검사 후, 같은 이벤트 ID의 중복 1행·50,000원을 제외하여 **3행·130,000원**을 반영했다.
- 잘못 지정한 양수 결제 해석은 오류로 표시됐고, 컬럼 선택을 유지한 채 취소를 포함하는 부호 유지로 수정했다.
- 새로고침 후 업로드 이력에서 결과를 다시 확인하고, 일별 **100,000원 / -20,000원 / 50,000원**의 첫 지표를 매시간 갱신으로 저장했다. 음수 축 눈금도 부호가 보이도록 축약 표시를 보완했다.
- 출처가 담긴 질문 초안을 직접 전송한 실제 모델 미리보기에서도 같은 세 값과 합계 130,000원을 확인했다. 추가 지표는 저장하지 않았다.
- 재접속 후 완료 상태와 저장 지표를 확인했다. 두 번째 빈 가게에는 첫 가게의 출처·지표가 표시되지 않았고, 첫 가게로 돌아오면 기존 지표가 유지됐다.
- 임시 평가 DB·API·웹을 정리하고 일반 프론트 빌드를 복원했다.
