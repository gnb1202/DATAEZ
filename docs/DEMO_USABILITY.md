## 확인한 문제와 변경

실제 Next.js 화면에 합성 API 응답을 연결해 변경 전 동작을 재현했다. 기존 저장 지표가 있는 가게에서 시작했으며, 오류 응답은 테스트 도구가 주입했다. 참여자를 관찰한 기록으로 해석하지 않는다.

| 변경 전 확인 | 변경 후 동작 |
|---|---|
| 대시보드가 있으면 샘플·내 파일 시작 버튼이 두 겹의 접힌 안내 안에 숨음 | 시작 버튼은 대시보드에 바로 표시. 사용 방법과 직접 지표 설정은 각각 접을 수 있음 |
| 질문 예시를 누르면 즉시 요청 전송 | 질문 예시와 답변의 후속 질문은 입력창에 초안으로 채우고 포커스 이동. 사용자가 편집한 뒤 전송 |
| 분석 응답 오류 뒤 질문과 기기 첨부가 입력창에서 사라짐 | 전송한 질문과 같은 File 객체를 복원. 긴 초안은 입력창 높이에 반영 |
| 보관함 파일을 선택한 분석이 실패하면 파일 범위는 남지만 질문은 사라짐 | 질문과 선택 파일·원본/누적 범위를 함께 유지 |

보관함의 마지막 버튼도 실제 동작에 맞춰 **선택한 파일을 채팅에 추가**로 바꿨다. 파일을 추가한 뒤 질문을 전송한다는 안내를 붙였다. Spoqa Han Sans Neo, Charcoal + Blue, 다크/라이트, 왼쪽 메뉴·오른쪽 채팅 구조와 계산·저장 API 계약은 유지했다.

## 실패에서 이어가기

- 분석 오류 또는 **응답 중지** 후 입력 초안과 첨부를 복원한다. 응답 수신 중지는 서버 작업의 취소·롤백을 보장하지 않는다.
- **이 대화의 처리 결과 확인**은 현재 대화의 저장 메시지를 GET으로 읽는다. 모델 요청, 파일 재업로드, 거래 반영, 지표 저장을 실행하지 않는다.
- 기록을 읽어도 초안·첨부를 유지한다. 완료된 답변이 없으면 다시 기록을 확인할 수 있고, 조회 자체가 실패해도 초안은 남는다. 이전 답변이 조회될 수 있으므로 이번 질문의 처리 내용인지 확인하도록 표시한다.
- 질문을 자동 재전송하지 않는다. 사용자가 처리 기록을 검토한 뒤 필요할 때 직접 수정·전송한다. 이 기능은 임의의 자연어 변경 요청을 반복해도 중복이 없음을 보장하는 기능이 아니다.
- 기존 저장 재시도 계약은 유지한다. 응답 유실 후 저장 키로 기존 위젯을 조회하고, 조회도 실패하면 같은 저장 키·설정으로 재시도한다.
- 가게 전환이나 새 분석은 이전 초안·복구 상태를 초기화한다. 채팅 닫기·메뉴 이동은 유지한다. 페이지 새로고침을 넘어 초안이나 기기 첨부를 영구 보관하지는 않는다.

### 실제 API·DB·LLM 재검증

`acceptance-20260910T125849Z`에서 실제 모델 질문 **1개**, 브라우저 점검 **6개**를 모두 통과했다. 합성 데이터를 사용하되 API 응답은 대체하지 않았다. 모델 설정은 `gpt-5.4`, 오케스트레이터 `gpt-5.4-nano`, 임베딩 `text-embedding-3-small`이다.

- 실제 로그인 → 예시 지표 3개 준비·반복 클릭 → 원본 파일·질문 초안 확인 → 자연어 요청 → 일별 원화 꺾은선·집계표·SQL 확인 → 저장·크기 조절을 수행했다.
- 원본 8행의 일별 합계는 **164,500 / 190,000 / 139,800 / 195,900원**으로 정확히 일치했다. 누적 장부에 30,000원 거래를 API로 추가한 뒤 원본 **690,200원**, 누적 **720,200원**을 각각 확인했다.
- 데모 웹·API·DB를 종료하고 다시 실행했다. 원본 파일 바이트, 대화, 저장 정의와 배치가 이전 값과 일치했다. 샘플 재시작의 취소는 상태를 바꾸지 않았고, 실행 시 새 샘플을 만들면서 기존 체험을 보존했다.
- [실제 검증 보고서와 소스 해시](evaluations/demo-usability/live-report.json). 비공개 실행 기록은 `.local-test/demo/acceptance-20260910T125849Z/`에 남겼다. 로그인·세션 파일은 공개 근거에 포함하지 않았다.

이 실제 검사는 정상 분석·저장·재접속의 회귀다. 의도적인 오류·응답 중단·조회 실패는 앞의 합성 API 검사에서 검증했다. 백엔드 코드·스키마 변경은 없으며, 이번 단계에서 전체 API 테스트나 자연어 평가 50문항을 다시 실행한 것은 아니다.

### 재실행

데모를 먼저 실행하고 저장소 루트에서 실행한다. 아래 UI 검사는 브라우저의 API 요청을 합성 응답으로 대체하며 사용자 데이터에 쓰지 않는다.

```powershell
$env:UI_BASE_URL='http://localhost:3000/dashboard'
node scripts/ui-eval/usability.cjs
node scripts/ui-eval/workspace.cjs
node scripts/ui-eval/file-library.cjs
node scripts/ui-eval/analysis-dashboard.cjs
```

원시 UI 결과는 `scripts/ui-eval/artifacts/`에 저장한다. `usability.cjs --audit`은 현재 코드의 점검 모드이며 과거 버전을 복원하지 않는다. 공개한 변경 전 근거는 변경 전 실행에서 확보했다. 실모델 검사 명령과 재시작·데이터 보존 범위는 [데모 실행 안내](DEMO_RUNBOOK.md#검증-재실행)를 따른다.

## 다음 직접 체험 — 관찰 대기

아래는 참여자가 해결할 과제다. 첫 시도에는 단계별 실행 안내를 미리 읽지 않고, 막힌 경우에만 도움을 받는다. 시간 측정은 로그인 뒤 시작한다. 테스트 도중 나온 숫자는 화면의 출처·기간과 함께 설명한다.

| 과제 | 완료할 일 | 관찰할 내용 | 사람의 결과 |
|---|---|---|---|
| 1. 샘플로 분석 | 샘플의 날짜별 결제 금액을 차트로 확인 | 시작 위치·전송 시점, 도움 없이 진행 여부 | 대기 |
| 2. 내 파일 준비 | 합성 CSV를 보관함에 올려 분석에 선택 | 보관과 분석 준비의 차이, 상태·다음 행동 이해 | 대기 |
| 3. 범위 설명 | 파일 원본과 누적 장부 중 목적에 맞는 범위 선택 | 장부에 거래를 추가하면 어느 결과가 바뀌는지 설명 | 대기 |
| 4. 첫 지표 저장 | 금액·단위·기간·취소 기준을 확인하고 저장 | 집계표·SQL 확인, 저장 전 미리보기 이해 | 대기 |
| 5. 후속 분석·수정 | 다른 기간으로 질문하고 저장 지표의 수정·이력 확인 | 새 결과와 저장본 변경을 구별하는지 | 대기 |
| 6. 가게 전환·재접속 | 다른 가게를 본 뒤 돌아와 저장 지표 찾기 | 어느 가게의 자료인지, 초안과 저장본 보존 차이 | 대기 |
| 7. 실패 복구 | 진행 중 응답 수신을 멈추고 기록을 확인한 뒤 이어가기 | 중지와 서버 취소의 차이, 중복 요청 없이 다음 행동 판단 | 대기 |

기록할 항목: 참여자 구분(실명 불필요), 데스크톱/모바일·테마, 과제별 성공/중단, 걸린 시간, 도움을 준 시점, 사용자의 설명, 재현 가능한 문제. 인증정보나 실제 고객 거래를 기록하지 않는다. 서버 장애를 일부러 만들어 사용자의 진행을 방해할 필요는 없으며, 저장 실패 등의 통제된 오류는 위 자동 검사의 근거를 사용한다.

프로젝트 사용자와의 첫 관찰은 아직 대기 중이다. PRD의 소상공인 **5명 중 4명 이상 첫 저장까지 10분 이내** 목표도 미검증이다. 내부 개선·자동 검사 완료만으로 Phase 2의 사용자 이해도 조건이나 시장 검증을 완료했다고 표시하지 않는다.
