# 공통 작업 공간 구현·검증

2026-09-09 · 프론트엔드 Phase 2 완료. 2026-09-10 후속 [Phase 4](ANALYSIS_DASHBOARD_UI.md)에서 ECharts와 저장 상태 UI를 통합했다. [실제 앱 화면 캡처](../outputs/frontend-design/app-workspace.html).

## 구현 결과

- 확정한 차콜 + 블루를 `web/app/theme.css`에 적용하고 기존 shadcn 의미별 색상에 연결했다. 기본 다크, 라이트, 시스템 선택을 헤더와 설정에서 제공한다. Spoqa 400·500·700은 기존 적용을 유지한다.
- 왼쪽에 현재 작업 가게·가게 추가·새 분석·대시보드·데이터 관리·분석 이력·설정/계정을 연결했다. 중앙에는 기존 대시보드·장부 화면 또는 선택한 분석 결과를 표시한다.
- 오른쪽 채팅은 기본 닫힘이며 버튼 또는 새 분석으로 연다. PC는 380/408px 패널, 1100px 이하에서는 포커스를 가두는 모달, 768px 미만에서는 왼쪽 메뉴도 모달로 제공한다.
- 입력·첨부파일·대화·결과를 가게별 작업 공간 상태로 분리했다. 메뉴 이동·채팅 닫기·화면 크기 변경 시 유지한다. 동일 가게의 출처 검토 링크도 전체 페이지 재접속 없이 데이터 관리로 이동한다.
- 새 분석은 현재 대화를 비우고 첫 질문 전에는 빈 대화를 서버에 만들지 않는다. 분석 이력에서 명시적으로 이전 대화를 선택해 결과와 후속 대화를 이어간다. 가게 변경은 해당 작업 공간을 재생성하므로 미전송 입력은 다른 가게로 넘어가지 않는다. 브라우저 전체 새로고침 후에는 서버에 저장된 이력에서 다시 열며 미전송 초안은 영구 저장하지 않는다.
- 대화 생성·이력 조회·메시지 조회에 요청 순서를 검사한다. 스트림마다 AbortController와 유휴 타이머를 분리하고 중단한 요청의 finally가 다음 요청의 상태를 지우지 못하게 했다. 중단은 응답 수신을 멈추는 동작이며 이미 처리된 서버 작업의 취소를 뜻하지 않는다.
- 대화 생성 실패는 초안을 남긴다. 스트림 오류는 표시하고 자동 재전송하지 않는다. 한글 조합 중 Enter로 요청이 전송되지 않게 했다.
- 중앙에서 기존 차트/집계표·SQL 상세와 대시보드 저장 API를 사용한다. 현재 작업 가게를 전체 집계 범위로 표시하지 않으며 여러 가게 지표의 실제 범위는 기존 상세에 유지한다.
- 기존 대시보드 드래그·리사이즈를 유지했다. 채팅이나 창 크기로 가용 폭만 달라졌을 때 배치를 저장하지 않고, 사용자의 드래그·리사이즈 종료 시 저장한다.
- 실제 차트는 이번 단계에서 Recharts를 유지하고 색상·축·범례·그리드·툴팁을 두 테마에 연결했다. 금액 원본 문자열과 툴팁 정밀도를 보존했다. 이후 Phase 4에서 ECharts로 교체했다.

## 검증

Windows Edge headless, 실제 Next.js production build, 테스트 API 응답 사용. 실사용 계정·DB·LLM은 이번에 연결하지 않았다.

| 검증 | 결과 |
|---|---|
| `cd web; npm run build` | 타입 검사 포함 통과 |
| `cd web; npm run lint` | 오류 0, 기존 경고 12 |
| `node scripts/ui-eval/workspace.cjs` | 14개 검증 그룹 통과 |
| `multi-metric.cjs` | 매핑·취소 차감·미리보기 실패·저장·주기·가게 전환 통과 |
| `import-validation.cjs` | 오류 위치 표시·파일 유지·재시도 통과 |
| `ledger-imports.cjs` | 출처 매핑·오류 재시도·오래된 미리보기·반영·재업로드·가게 전환 통과 |
| `event-review.cjs` | 거래 출처·중복 후보 결정·충돌 차단·장부 전환·가게 분리 통과 |
| 브라우저 스크립트 구문 | 15개 파일 통과 |

공통 화면 검증에는 채팅을 닫은 중간 응답, 가게 전환 후 늦은 메시지, 대화 생성 중 새 분석, 첨부 유지, 시스템 테마 변경, 320–1440px 화면, 모바일 Tab/Escape와 포커스 복귀, 차트 소수점·툴팁, 드래그·리사이즈 저장, 동일 가게 링크 이동이 포함된다. [세부 결과 JSON](../outputs/frontend-design/workspace-app/results.json). 화면 캡처는 다크·라이트·모바일을 직접 확인했다. 이 검증이 서비스 전체의 접근성 인증을 의미하지 않는다.

ESLint 9/Next의 flat config로 전환했다. 기존 폼의 동기 상태 초기화 3건과 사용하지 않는 UI sidebar의 난수 skeleton 1건에 대한 React Compiler 진단은 해당 파일에 한해 경고로 유지했다. 나머지 경고는 기존 unused 변수 4건, effect 의존성 2건, 가상화 라이브러리 진단 1건, 불필요한 disable 1건이다. 새로운 작업 공간 코드에는 lint 경고가 없다.

기존 실제 모델 검증 스크립트는 새 내비게이션·명시적 이력 열기에 맞춰 수정하고 구문을 확인했으나, 실제 모델/DB 전체 수용 시나리오를 이번에 재실행하지 않았다. 로컬 production 빌드는 API URL 미설정으로 `http://localhost:8000`을 사용한다. 실제 로그인에는 실행 중인 API가 필요하다. 3131은 기존 시안·캡처 서버이며 실제 앱은 3132에서 별도로 실행한다.
