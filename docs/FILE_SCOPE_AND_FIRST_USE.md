# 분석 범위·저장 설정·첫 사용 안내

2026-09-10. 앞선 통합 검증에 이어 세 작업을 함께 구현했다.

## 사용 흐름

1. 파일 보관함에서 파일을 연결한 뒤 **파일 원본만 / 누적 장부 전체**를 선택한다. 새 선택은 원본만이 기본이다. 기존 대화의 범위 없는 선택은 종전처럼 누적 장부로 해석한다.
2. 자연어 질문으로 재계산 가능한 지표와 그래프를 만든다. 채팅의 선택 파일, 답변 출처, 분석 결과, 저장 설정, 저장된 위젯과 집계표에 범위를 표시한다.
3. **대시보드에 저장**을 누르면 이름·단위·기간·갱신 주기를 검토한다. 현재 설정으로 미리보기를 계산해야 저장할 수 있다. 기간이나 단위를 바꾸면 이전 미리보기는 무효화된다.
4. 대시보드의 **샘플 데이터로 시작**은 별도 `샘플 가게 · 모퉁이 카페`와 가상 거래 8행을 준비한다. 파일 원본을 선택하고 질문 초안을 채운다. 사용자가 질문을 전송한 뒤 결과와 저장 설정을 확인한다.

내 파일로 시작하는 경로와 기존 결제·현금 장부 안내도 유지한다. 글꼴은 Spoqa Han Sans Neo, 색상은 Charcoal + Blue이며 다크·라이트를 지원한다.

## 분석 범위의 계약

| 범위 | 데이터 | 새로고침 |
|---|---|---|
| 파일 원본만 | 보관한 원본 바이트를 검사·파싱한 읽기 전용 행 | 같은 원본 행에 저장된 기간·필터를 다시 적용 |
| 누적 장부 전체 | 선택한 파일과 연결된 장부의 현재 거래 | 이후 장부에 반영한 거래도 포함 |
| 선택 문서 | 기존 문서 검색 경로 | 선택 문서의 검색 준비 상태에 따름 |

원본 분석 자료는 `(계정, 가게, 원본 파일)`별로 한 번 생성한다. 원본 내용 해시를 확인하며, 이미 변경된 장부를 복사하지 않는다. 원본과 장부는 서로 다른 `table_id`를 사용하므로 저장 지표의 기존 실행 계약으로 출처를 고정할 수 있다. 일반 장부 목록·장부 개수·검색 색인에서는 원본 분석 자료를 제외한다.

원본 자료에는 DB 쓰기 차단 트리거가 있고, 일반 REST·AI 수정 경로에서도 변경·삭제·장부 채택을 차단한다. 같은 연결 장부의 원본 범위와 누적 범위를 동시에 선택하거나 같은 파일을 두 번 선택하면 명시적인 오류를 반환한다. 여러 장부 합계의 같은 원본 중복 검사도 유지한다. 서로 다른 파일 사이의 실제 거래 중복 여부를 자동으로 판정하는 기능은 아니다.

보관함에서 제외하면 새 분석에서 다시 선택할 수 없다. 기존 저장 지표와 원본 기록은 유지하는 기존 제외 정책을 따른다. 가게 삭제 시에는 그 가게의 지표 출처도 사용할 수 없다. 원본 파일의 새 버전을 자동으로 따라가는 기능은 없다. 원본만 선택했더라도 ‘이번 달’ 같은 상대 기간은 시간이 지나면서 결과가 달라질 수 있다.

## 저장 설정과 재시도

- 단일 장부 지표의 표시 단위는 미지정·원화·건·일반 숫자다. 금액 환산은 하지 않는다. 행 건수는 건수로 고정한다.
- 여러 장부 합계와 계산식은 검증된 통화·계산 단위를 유지한다. 계산식 양쪽 기간은 각각 표시하며, 기존 호환성 검증을 적용한다.
- 갱신은 수동·매시간·24시간마다 중 선택한다. 파일 원본의 갱신은 누적 장부의 새 거래를 가져오지 않는다.
- 응답이 유실되어도 같은 분석 결과를 중복 저장하지 않는다. 재시도 중에는 최초 제출한 설정과 요청 본문을 고정한다. 기존 단위 필드 없는 지표의 저장 키도 호환된다.

## 첫 사용 데이터

`POST /api/library/files/sample-workspace`는 계정별 샘플 가게를 재사용한다. 가게 생성과 파일 보관·연결이 부분적으로 완료되어도 재시도할 수 있다. 기존 사용자 가게를 비우거나 거래를 덮어쓰지 않는다. 다른 계정에는 별도 샘플 가게와 파일을 만든다.

샘플은 2026-09-01~04의 카드·현금·음수 취소 8행, 총 **690,200원**이다. 질문 초안은 전체 기간을 사용하며 실제 매출이 아닌 가상 데이터임을 안내한다. 질문 전송이나 지표 저장은 자동으로 실행하지 않는다.

Phase 1에서는 **예시 대시보드 보기**와 **샘플 체험 다시 시작**을 추가했다. 예시 버튼을 직접 누르면 원본 범위의 미리 정의한 지표 3개를 저장 키로 중복 없이 준비한다. 재시작은 현재 샘플 소유권·대상 ID·요청 ID를 확인한 뒤 새 샘플을 만들고 이전 체험은 보존한다. `GET /sample-workspace`, `POST /sample-workspace/dashboard`, `POST /sample-workspace/restart`를 기존 보관함 경로에 추가했으며, 마이그레이션 `014_sample_restarts.sql`도 서버 시작에 적용한다. [실행과 보존 정책](DEMO_RUNBOOK.md) · [별도 검증 기록](DEMO_ACCEPTANCE.md)

## 검증

후속 Phase 2에서는 시작 버튼 노출, 질문 예시의 초안 작성, 분석 오류·중지 후 초안과 첨부 복원, 저장된 처리 기록 조회를 추가했다. [최신 사용성 동작·별도 검증·직접 체험 과제](DEMO_USABILITY.md)를 참고한다. 아래 수치는 이 문서의 원래 단계 검증 기록이다.

최종 회귀 검사: 백엔드 **222 passed / 67 skipped**, 브라우저 **32개** 흐름 통과(분석·저장 12개, 보관함 6개, 작업 공간 14개). 최종 Next.js 빌드·TypeScript·변경 파일 ESLint도 통과했다. 67개는 pgvector 전용 테스트 DB 또는 별도 SQL 평가 의존성을 설정하지 않아 실행하지 않은 기존 검사다. 새 원본 범위와 샘플 관련 테스트는 모두 실행했다.

- 실제 PostgreSQL: 원본 합계 **330,000.06원**과 추가 거래 후 장부 합계 **360,000.15원** 분리, 원본 불변성, 동시 재선택, 저장·갱신·권한·제외 후 정책, 샘플 생성 중복 방지.
- 재계산 정의 없는 일반 그래프의 저장 화면에서 미리보기 미생성 상태를 처리하는 오류를 수정했고, 실제 브라우저로 저장·이동·크기 조절을 다시 검증했다.
- 실제 프론트와 API 응답 fixture: 기간 변경 후 미리보기 무효화, 검토한 설정 제출, 실패 시 동일 본문 재시도, 저장 상태 복원, 다크·라이트와 좁은 화면.
- 실제 브라우저 → API → 설정된 LLM → PostgreSQL: 자연어 질문 **6개**, 확인 항목 **29개** 통과. 원본 범위 분석과 재접속, 샘플 시작부터 첫 대시보드 저장까지 포함했다. 자동 갱신은 테스트 위젯의 예정 시각을 앞당겨 실제 스케줄러로 검증했다.
- 통합 실행: `dataez_workspace_live_8f227a173631429085f4004481598d42`. 테스트 DB를 제거했고 기본 프론트 빌드를 복구했다. 원본 로그·세션은 ignored artifacts에 보관한다.
- 첫 실행은 Windows의 PostgreSQL 연결 프로세스 생성 실패(error 1455)로 중단됐다. 테스트의 반복 DB 연결을 공개 API의 기존 풀 사용으로 바꾸고 풀 크기를 제한한 뒤 전체 흐름을 다시 실행했다.
