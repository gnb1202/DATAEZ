# F — 실제 RAG 검색과 채팅 지표 저장 검증

2026-09-08. **실제 임베딩·pgvector 검색 20문항을 3회 실행해 모두 1위로 정답 자료를 찾았다.** 실제 채팅 화면에서 검색 → 순결제액 1,358,000원 저장 → 같은 지표를 매시간 갱신으로 변경하는 흐름도 통과했다. 이는 작은 합성 자료의 기능 검증이며 실제 사업자의 검색 성공률을 뜻하지 않는다.

전체 질문·검색 후보·모델 답변·검사 결과는 [평가 기록](evaluations/rag-2026-09-08.json), 화면은 [검증 대시보드](evaluations/rag-2026-09-08-dashboard.png)에 있다. E의 금액·반복 업로드 평가는 [별도 기록](PG_SAMPLE_EVALUATION.md)을 참고한다.

## 달라진 동작

1. **파일과 업무 의미를 함께 검색한다.** 장부명·컬럼 외에 원본 파일명, 연결 출처·제공자·자료 종류, 원본 금액/일시 매핑, 실제 데이터 기간을 색인한다. 관리 원장은 승인·환불·순결제액의 의미도 포함한다. 예를 들어 `01_gangnam_pg.csv`나 “현금으로 받은 돈”으로 해당 장부를 찾는다.
2. **검색 오류를 자료 부재와 구분한다.** 비활성은 `rag_disabled`, 장애는 `rag_unavailable`, 색인이 없는 장부는 `index_incomplete`로 알린다. 모델은 장부 목록·구조 조회로 확인 범위를 보완한다. 후보 순위는 정답 확률이 아니므로 출처·기간·컬럼 의미를 확인한 뒤 SQL로 계산한다.
3. **가게와 소유자를 실제 원본까지 확인한다.** 벡터 행뿐 아니라 연결된 장부·파일·가게의 소유권과 삭제 상태를 검색 전후에 검사한다. 현재 가게에서 다른 가게의 문서를 삭제할 수 있던 경로도 수정했다.
4. **문서 교체는 한 번에 반영한다.** 전체 청크의 임베딩을 먼저 준비하고, 한 DB 트랜잭션에서 기존 청크를 교체한다. 두 번째 임베딩 배치나 SQL 저장이 실패해도 기존 문서 전체가 유지된다. 외부 API를 기다리는 동안 DB 행 잠금을 유지하지 않는다.
5. **오래된 색인 쓰기를 차단한다.** 임베딩 전후의 카탈로그를 비교해 중간 변경이 있으면 오래된 결과를 저장하지 않는다. 임베딩 응답의 개수·차원·유한값과 입력 순서를 검사하며, 채팅의 검색 임베딩 사용량도 해당 턴에 포함한다.

검색은 cosine 벡터 순위와 PostgreSQL 전문 검색의 `ts_rank_cd` 순위를 RRF로 합친다. 기존 코드 주석의 BM25 표기는 실제 구현과 달라 바로잡았다. 연산자·설치 방식은 [pgvector 공식 문서](https://github.com/pgvector/pgvector)를 참고했다.

| 검사 | 결과 |

| 실제 모델의 검색 후 순결제액 조회 | 3회 모두 **1,358,000원**, 저장 없음 |

| 검색 임베딩 사용량 | 동기·SSE 턴에 기록 확인 |
| API 전체 회귀 검사 | **521 passed**, skip 없음 |
| 웹 빌드 | Next.js 빌드·TypeScript 검사 통과, 일반 API 주소로 빌드 복구 |

검증 가게에는 장부 9개와 문서 3개를 두었다. 결제·현금·정산·예약·운영지출·8월/9월 요약·재고·쿠폰 자료를 구분하고, 다른 가게와 다른 소유자에게 동일 파일명·유사 내용을 배치했다. 문서는 각각 짧은 합성 규정이므로 문서 top-3보다 **top-1** 결과에 의미가 있다. 대규모 문서 검색·ANN 성능은 평가하지 않았다.

실제 HTTP 업로드·미리보기·후보 판정·반영·문서 색인을 거쳤다. 모델 응답·검색 벡터·브라우저 요청을 모의 값으로 대체하지 않았다. 별도 pytest의 트랜잭션/장애 테스트는 의도적으로 고정 벡터를 사용하며 검색 품질 평가와 구분한다.

브라우저 검사 과정의 실패도 기록에 남겼다. 첫 실행은 세션 복원 중 강제 페이지 이동, 두 번째는 대화 로딩 완료 전 입력, 세 번째는 실제 값 `1358000`에 천 단위 쉼표가 있어야 한다는 잘못된 검사 가정으로 실패했다. 화면 준비 상태와 실제 숫자를 기준으로 수정한 마지막 실행은 채팅부터 DB 대조까지 통과했다. 로그인 중 새로고침 내구성이나 다중 탭 인증 동시성까지 해결했다는 뜻은 아니다.

첫 RAG 모델 실행에서는 단일 장부 지표에 version=2를 전달한 호출이 거절된 후 올바른 호출로 회복했다. 주요 요청의 결과는 맞았지만 불필요한 후속 기능 제안·내부 용어·긴 답변은 개선 대상으로 남아 있다. 독립 사업자 평가자는 참여하지 않았다.

## 실행과 기존 자료 적용

- 검증 DB: 루프백 Docker PostgreSQL 16, **pgvector 0.8.2**. 사용 이미지 digest: `pgvector/pgvector@sha256:7d400e340efb42f4d8c9c12c6427adb253f726881a9985d2a471bf0eed824dff`.
- 임베딩: `text-embedding-3-small` 1536차원. worker/router는 프로젝트의 `gpt-5.4` / `gpt-5.4-nano` 설정을 사용했다.
- 임의 이름의 DB를 생성하고 실행 후 삭제한다. 사용자 앱 데이터에는 샘플을 자동 반영하지 않았다. 검증용 컨테이너·PostgreSQL도 종료했다.
- 저장된 사용량은 검색 질문·채팅 턴 기준이다. 초기 파일 색인 임베딩 전체 비용을 합친 수치가 아니며, 코드 요율표의 추정액은 실제 청구액이 아니다.

재실행에는 로컬 CREATE DATABASE 권한과 실제 API 키, pgvector, Python/API·Node/웹·Playwright 의존성이 필요하다. 프로젝트 루트에서 실행한다.

```powershell
$env:DATAEZ_RAG_TEST_DATABASE_URL='postgresql://dataez_test@127.0.0.1:55440/postgres'
python scripts/rag-eval/run.py --browser
```

검색 평가를 반복하지 않고 화면만 재확인하려면 `--browser-only`를 사용한다. 이 모드도 새 DB와 실제 HTTP 업로드·임베딩을 사용한다. API 키는 환경변수/프로젝트 `.env`에서 읽으며 출력하지 않는다. 원본 실행 로그와 테스트 로그인 정보는 Git에서 제외한 `scripts/rag-eval/artifacts/`에 남는다.

기존 장부는 새 카탈로그 형식으로 **재색인해야** 파일명·기간 검색 보강이 적용된다. `api/`에서 `python ../scripts/reindex_catalog.py --help`로 사용법을 확인한다. 사용자 ID와 가게 ID를 지정하면 기본 동작은 변경 필요 여부만 조회한다. `--apply`를 붙이면 해당 가게의 변경된 장부만 실제 임베딩 API로 갱신한다. 원본 장부·지표·문서는 수정하지 않는다. 이번 작업에서는 사용자 운영 DB에 실행하지 않았다.

## 남은 범위

- 실제 PG 공식 파일과 사업자 검증. 결제수단·채널·수수료 선택 보존과 자연어 지표는 이후 [G](PAYMENT_ATTRIBUTES.md)에서 구현·검증했다.
- 최근 파일명 최대 20개 범위를 넘어선 자료 검색, 큰 원장의 기간 계산 비용, 대량 문서 성능 평가.
- 색인 실패의 영속 작업 큐·자동 재시도·상태 화면은 이후 [I](SEARCH_INDEX_JOBS.md)에서 완료했다. 앱의 변경 경로에 연결하고 대기·실패 색인을 검색 도구에서도 알린다. 운영자가 DB를 직접 변경하는 경우까지 자동 감지하지는 않는다.
- I 이후 문서 등록과 작업을 함께 저장하고 첫 색인 실패도 목록에 표시한다. 스토리지 고아 객체 정리와 과거 실패 업로드의 가게 식별은 별도 과제다.
- 문서 재업로드 버전 관리, 파일 원문 미리보기와 근거 연결 UX.
- F에서는 서버 스케줄러를 껐으므로 갱신 **설정 저장**까지 검증했다. 브라우저 종료 후 실제 주기 실행·재시작 복구는 [D의 검증](INTEGRATED_ACCEPTANCE.md)에 있다.

F에서 제안한 PG 추가 속성 보존과 결제수단·채널별 지표는 [G](PAYMENT_ATTRIBUTES.md), 기존 관리 출처의 과거 속성 복원은 [H](ATTRIBUTE_RESTORATION.md)에서 완료했다. 색인 작업 큐·자동 재시도·상태 표시는 [I](SEARCH_INDEX_JOBS.md)에서 완료했다. 실제 사업자 파일 파일럿은 남아 있다.
