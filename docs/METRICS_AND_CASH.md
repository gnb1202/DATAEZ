# K·L: 계산식 지표와 현금 직접 입력

2026-09-08. 실제 PG 파일 파일럿은 서비스 일정이 정해질 때까지 보류하고, 사용자 요청에 따라 J보다 K·L을 먼저 구현했다.

후속으로 [v4 그룹별 계산식 그래프와 집계표·SQL](FORMULA_CHARTS.md)을 추가했다. 아래 K의 v3 범위는 숫자 하나를 만드는 계산식에 해당하며, 날짜·채널별 계산식은 후속 문서를 참고한다.

## 사용할 수 있는 기능

| 구분 | 구현한 기능 | 사용 위치 |
|---|---|---|
| K | 두 집계의 차이·비율·증감률, 계산 기준과 출처 표시 | AI 분석 → 미리보기·대시보드 저장 |
| K | 저장 지표의 기간·필터·제목·정의 수정 | AI 분석 또는 위젯의 수정·이력 → 고급 정의 편집 |
| K | 변경 이력 조회, 이전 정의로 복원 | 위젯의 수정·이력 또는 AI 분석 |
| L | 현금 수납·취소의 날짜·금액·채널·메모 입력 | 장부 관리 → 현금 직접 입력 |
| L | 자연어 입력 초안과 검토 화면 연결 | AI 분석 → 현금 입력 검토하기 |
| L | 재전송 방지, 유사 거래 확인, 반영 이력 | 현금 직접 입력 화면 |

대화 예시:

- “결제원장 전체 기간의 순결제액에서 PG 수수료를 뺀 지표를 매시간 갱신하도록 저장해줘.”
- “그 지표의 두 집계 기간을 이번 달로 수정해줘.”
- “이번 달 취소 금액 절댓값을 승인 금액으로 나눈 취소율을 보여줘.”
- “이번 달 순결제액의 전월 대비 증감률을 미리 보여줘.”
- “현금 매출 3만원을 기록해줘. 메모는 점심 매출이야.”

현금 요청은 **초안 작성**까지 실행한다. 답변 아래 검토하기 버튼으로 이동해 내용을 확인하고 **현금 장부에 반영**을 누른다. 같은 초안의 반영을 다시 요청해도 실제 장부에는 한 번만 저장된다. 지표는 수동 재계산 또는 기존 자동 갱신 주기에 새 거래를 포함한다.

## K 계산 규칙

기존 v1 단일 장부·v2 여러 장부 합계는 유지한다. 새 v3는 같은 가게에 속한 두 개의 v1 스칼라 집계를 피연산자로 받는다. 각 집계에 자체 날짜 컬럼·기간·필터를 저장한다.

| 연산 | 계산 | 결과 단위 |
|---|---|---|
| difference | 왼쪽 − 오른쪽 | 입력 단위 |
| ratio | 왼쪽 ÷ 오른쪽, 필요 시 × 100 | 숫자 또는 % |
| percent_change | (왼쪽 − 오른쪽) ÷ 오른쪽 절댓값 × 100 | % |

- 두 피연산자의 단위가 같아야 한다. 건수 집계는 count 단위를 사용한다. 필요 시 집계 결과의 절댓값을 명시한다.
- 두 집계는 하나의 SQL 스냅샷에서 계산한다. 금액은 Decimal을 유지하며 차감은 정밀도를 보존한다. 비율은 소수점 넷째 자리까지 ROUND_HALF_EVEN 규칙으로 반올림한다.
- 분모가 0이거나 집계할 행이 없으면 `계산 불가`와 원인을 저장한다. 0%로 대신 표시하지 않는다. 범위 내 숫자 NULL은 기존 규칙대로 계산을 거절한다.
- 취소율은 **금액 비율인지 건수 비율인지** 구분한다. 수수료 원본 부호를 보존하며 수수료 차감액을 정산 입금액·순이익으로 설명하지 않는다.
- 이번 달/지난달은 한국 시간의 각 달 전체 범위다. 아직 마감되지 않은 이번 달에 대한 안내를 표시한다. 동일 경과일 비교는 별도 기능이다.
- v3는 KPI를 만든다. 그룹별 계산식 차트, 재귀 수식, v2 통합 합계를 피연산자로 하는 수식, 임의 코드 실행은 지원하지 않는다.

## K 수정·복원 계약

`metric_definition_revisions`에 제목·전체 정의·버전·변경 시각·복원 출처를 저장한다. 기존 지표는 논리적 버전 1이며 첫 수정 때 기준 정의를 이력에 보존한다.

변경 요청은 `expected_revision`과 `request_key`를 포함한다. 현재 버전과 다르면 409로 거절하며, 같은 요청을 다시 보내면 이전 적용 결과를 재사용한다. 위젯 행 잠금으로 수정·복원·갱신을 직렬화한다. 이력 조회도 같은 위젯에 공유 잠금을 잡아 최신 정의와 이력이 섞이지 않게 한다.

수정·복원은 widget ID·위치·크기·갱신 주기를 유지한다. 새 정의를 현재 데이터로 계산한 뒤 정의·결과·이력을 함께 저장한다. 계산 실패 시 이전 정의·결과·이력이 유지된다. 복원은 과거 수치를 복사하는 기능이 아니다. 과거 정의로 현재 데이터를 다시 계산하고 새 버전을 추가한다.

HTTP 이력과 화면은 페이지 단위로 조회한다. 대화 도구는 JSON을 중간에서 자르지 않고 `next_offset`으로 다음 이력을 탐색한다.

## L 기록 규칙

- 가게당 하나의 현금 직접입력 출처를 첫 반영 시 자동 생성한다. `input_mode=cash`로 구분하고 파일 업로드·속성 복원·일반 행 수정 경로를 차단한다.
- 입력 금액은 양수, 최대 소수점 두 자리와 정수부 20자리다. 수납은 양수, 취소는 음수로 원장에 기록한다. 실제 결제·환불을 실행하지 않는다.
- 입력은 **거래 일자** 기준이다. `occurred_at`에는 해당 한국 날짜의 자정을 저장하며 실제 거래 시각을 의미하지 않는다. 화면·장부 설명·검색 카탈로그·대화 지침에 이를 명시한다.
- 결제수단은 현금, 채널은 미입력 시 NULL이다. PG 수수료는 수집하지 않는다. 메모는 원장 숫자 컬럼과 분리해 입력 이력에 보존한다.
- 취소 시 원거래 ID를 선택적으로 연결할 수 있다. 같은 가게의 현금 승인 거래인지 확인하며, 원거래 전체 취소 잔액 대사는 이 단계의 범위가 아니다.
- 초안은 24시간 동안 반영할 수 있다. 취소·만료 초안은 반영할 수 없다. 반영된 기록을 초안 취소로 지우거나 덮어쓰지 않는다.
- 같은 가게·날짜·종류·금액의 반영된 기록을 중복 의심으로 보여준다. 사용자가 기존 기록을 확인하고 별도 거래임을 표시해야 추가 반영한다. 다른 출처에 기록된 동일 거래의 자동 중복 판단은 하지 않는다.
- 초안 요청 키와 확인 토큰을 사용한다. 가게 현금 출처를 잠근 뒤 중복 의심을 다시 검사하므로 동시 반영에서도 검사를 우회하지 못한다.
- 물리 원장 행, `source_events`의 출처 추적, `cash_entries` 상태, 행 수, 출처 데이터 버전을 하나의 DB 트랜잭션으로 반영한다. I의 검색 outbox도 같은 커밋에서 갱신된다.

## API와 마이그레이션

| API | 기능 |
|---|---|
| `PUT /api/projects/{pid}/metrics/{mid}` | 지표 정의 수정 |
| `GET .../metrics/{mid}/history` | 수정 이력 |
| `POST .../metrics/{mid}/restore` | 정의 복원 |
| `POST /api/projects/{pid}/cash-entries/drafts` | 현금 초안 |
| `POST .../cash-entries/{id}/commit` | 확인한 초안 반영 |
| `GET .../cash-entries` | 현금 입력 이력 |
| `GET .../cash-entries/{id}` | 초안·반영 기록 상세 |
| `DELETE .../cash-entries/{id}` | 미반영 초안 취소 |

모든 경로는 로그인 소유자와 선택 가게 범위에서 동작한다. `008_metric_definition_revisions.sql`, `009_cash_entries.sql`과 동일한 멱등 DDL을 API 시작 시 적용한다. 이 작업에서 운영 DB를 변경하거나 배포하지 않았다.

## 검증

재현 명령:

```powershell
$env:DATAEZ_TEST_DATABASE_URL = 'postgresql://test@127.0.0.1:55439/postgres'
$env:DATAEZ_RAG_TEST_DATABASE_URL = 'postgresql://test@127.0.0.1:55440/postgres'
python -m pytest api/tests -q
python scripts/metrics-cash-eval/run.py
```

두 번째 명령은 loopback의 새 pgvector DB만 사용한다. 실제 모델·임베딩 API를 호출하고, 실제 Edge 브라우저·HTTP API를 검증한다. 테스트 DB·API·브라우저를 종료하고 일반 웹 빌드를 복원한다. 생성된 테스트 로그인 정보·업로드 원본·전체 로그는 Git에서 제외한다.

최종 전체 API 검증은 **626개 통과, skip 0개**이며 K·L 관련 신규 검사는 37개다. TypeScript와 production build를 통과했다. 실제 모델·브라우저 전체 시나리오를 두 번 통과했으며 마지막 실행은 `dataez_kl_eval_11e27873608d41099c528b2d30374970`이다.

- 자연어 계산식 저장 368,600원 → 이번 달로 수정 271,600원 → 같은 위젯의 이전 정의 복원 368,600원.
- 자연어 금액 취소율 6.6667%, 전월 대비 증감률 180%가 원본 집계와 일치.
- 현금 초안·화면 반영·동일 금액 별도 거래 확인 후 3건 110,000원. 취소 5,000원 반영 후 저장 지표 105,000원으로 재계산.
- 동시 확인·재전송·중복 의심·실패 롤백·가게 격리·수정 충돌·정의 복원·이력 페이지 탐색을 검사.

기존 ESLint 9와 레거시 `.eslintrc` 설정의 충돌로 lint는 완료하지 못했다. TypeScript·빌드 결과와 별도로 남아 있는 검증 도구 설정 문제다. 초기 브라우저 실행의 복원 버튼 실패는 검증 스크립트가 표시 문구로 aria-label을 찾으려던 오류였으며, 선택자를 수정한 후 통과했다.
