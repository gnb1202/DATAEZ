# H — 기존 출처의 과거 속성 복원

이미 등록한 관리 출처에 미연결 결제수단·판매채널·PG 수수료를 추가할 수 있다. 거래를 다시 적재하는 대신, 검증된 원본에서 속성만 복원한다. 출처와 장부 ID, 기존 거래의 금액·ID·일시, 저장 지표의 정의·레이아웃·갱신 주기는 유지한다.

## 화면 사용

1. **장부 관리 → 출처별 파일 반영**에서 기존 출처를 선택한다.
2. **과거 속성 복원**을 열고 추가할 정보의 원본 컬럼 이름을 입력한다. 하나 이상 선택하며 이미 연결된 속성은 변경할 수 없다.
3. **원본 검사·복원 미리보기**에서 전체 거래 수, 제공/미제공 건수, 미반영 업로드 수, 복원 예시의 원본 파일·행을 확인한다.
4. 오류가 없으면 **검사한 속성 복원 적용**을 누른다. 검사는 30분 동안 유효하고, 그 사이 장부·업로드 상태가 바뀌면 다시 검사해야 한다.
5. **변경 행 보기**에서 모든 행의 복원 전·후 값과 원본 반영 기록을 확인한다. 원본 반영 기록은 당시 내용으로 보존된다.

숫자 빈칸은 0원이 아닌 NULL(미제공)로 보존한다. PG 수수료는 원본 부호를 유지한다. 누락 수수료를 포함한 전체 합계 계산은 G의 규칙대로 중단하며, 명시한 제공분 또는 미제공 건수 지표를 별도로 만들 수 있다.

## 원본을 확인하는 방식

| 출처의 저장 방식 | 복원 근거 | 장부 변경 |
|---|---|---|
| canonical: 처음부터 관리 출처로 만든 원장 | 각 `source_events`의 최초 완료 배치와 원본 행 번호. 파일 크기·SHA-256을 검증한 뒤 해당 행만 읽는다. | 선택 속성 컬럼을 추가하고 같은 `_row_id`에 값 저장 |
| original: 기존 일반 장부를 관리 출처로 전환 | 이미 보존된 원본 장부 컬럼과 전체 행. 수수료는 숫자 컬럼이어야 한다. | 물리 행을 변경하지 않고 매핑과 비교 기록에 속성을 연결 |

금액·ID·일시·기존 연결 속성이 현재 장부/비교 기록과 일치하는지 먼저 검사한다. 중복 검색 키와 후보 검색 해시도 검증한다. 원본 파일이 없거나 바뀌었거나 최초 반영 행이 확인되지 않으면 전체 적용을 막는다. 등록된 기본 필드나 이미 연결된 속성을 덮어쓰는 기능은 아니다.

ID 없는 거래도 최초 반영 파일·행 번호를 사용한다. 같은 날짜·금액이라는 이유로 다른 거래의 속성을 가져오지 않는다. 제외한 중복 후보와 나중에 올라온 중복 파일은 복원 근거로 쓰지 않는다. 선택되지 않은 원본 행의 추가 속성 파싱 오류도 다른 거래에 영향을 주지 않는다.

canonical 장부의 오래된 기준점에 최초 배치 정보가 없으면 추측 복원을 지원하지 않는다. original 장부의 기준점은 보존된 물리 컬럼을 검증하므로 배치 파일이 없어도 연결할 수 있다.

## 원자성·재시도·버전

검사 시 짧은 출처 잠금으로 장부·이벤트·원본 파일 메타데이터·대기 업로드 상태를 읽고 fingerprint를 만든다. 파일 읽기와 파싱은 DB 트랜잭션 밖에서 수행한다. 검사 결과를 저장하기 전에 상태를 다시 확인한다.

적용할 때도 원본을 다시 읽고 검증한다. 최종 트랜잭션은 출처 → 검사 기록 → 장부 메타데이터 → 물리 테이블 순으로 잠그고 fingerprint를 재확인한다. 다음 항목을 하나의 트랜잭션으로 반영한다.

- 선택 속성의 컬럼과 값, 현재 `source_events.normalized/content_hash`.
- 출처의 새 매핑, `rule_version + 1`, `data_revision + 1`.
- 행별 복원 전·후 값과 근거를 담은 `source_attribute_changes`.
- 검사 완료 상태와 결과, 대기 업로드의 기존 미리보기·후보 결정 무효화.

중간에 실패하면 컬럼 생성까지 모두 롤백한다. 같은 검사 ID로 적용을 반복하거나 동시에 요청하면 한 번만 반영하고 저장된 완료 결과를 반환한다. 금액·통화·종류·일시를 바꾸지 않으므로 후보 검색 해시와 이벤트 식별 키는 유지한다.

과거 완료 배치의 행 판정·포함/제외 결정·요약·금액은 수정하지 않는다. 복원 전후 차이는 별도 이력에서 확인한다. 규칙 변경 후에는 다음과 같이 처리한다.

| 요청 | 동작 |
|---|---|
| 과거 완료 요청 키와 같은 파일을 재시도 | 원래 완료 결과 재반환 |
| 같은 요청 키에 다른 파일 | 기존과 같이 거부 |
| 새 요청으로 같은 파일 업로드 | 새 규칙 배치에서 검증, 복원한 이벤트와 같으면 추가 0건 |
| 규칙 변경 전 미반영 파일 | `requires_reupload=true`. 이전 미리보기/결정 사용 불가, 새 파일 선택·업로드 필요 |
| 새 거래가 포함된 파일 | 기존 거래는 중복 제외하고 신규 거래만 추가 |

미반영 파일의 24시간 보관/정리 정책은 유지한다. 복원 적용 자체는 저장 지표를 다시 생성하거나 자동 계산하지 않는다. 기존 수동·주기 갱신에서 같은 정의를 실행한다.

검색 색인은 장부 트랜잭션 완료 후 갱신한다. 성공은 `index_status=updated`, 미갱신은 `not_updated`로 표시한다. 색인 실패로 완료한 장부를 되돌리지 않는다. 현재는 해당 가게의 카탈로그 재색인으로 보완하며 영속 색인 작업 큐는 후속 과제다.

## API와 저장 구조

모든 경로는 `/api/projects/{project_id}/ledger-sources/{source_id}` 아래에 있으며 소유자·가게·출처·검사 기록의 소속을 검증한다.

| 메서드·경로 | 역할 |
|---|---|
| POST `/attribute-restorations/preview` | 선택 컬럼 검사와 30분 유효한 검사 ID 발급 |
| POST `/attribute-restorations/{id}/apply` | 재검증 후 적용 또는 완료 결과 재반환 |
| GET `/attribute-restorations` | 최근 20개 검사·적용 이력 |
| GET `/attribute-restorations/{id}/changes?limit=50&offset=0` | 복원 전후 행 기록과 원본 파일명·배치·행 위치 |

검사 요청 예시:

```json
{
  "payment_method_column": "결제수단",
  "channel_column": "판매채널",
  "fee_column": "PG수수료"
}
```

`006_attribute_restoration.sql`에 검사/적용 테이블과 행별 이력 테이블을 추가했다. 기존 004/005 구조 이후에 적용한다. 앱 시작의 `ensure_ledger_import_tables()`에서도 같은 DDL을 멱등적으로 적용한다. 기존 출처의 데이터나 매핑은 이 마이그레이션으로 자동 변경하지 않는다.

검사는 출처당 최대 100,000행, canonical 원본 최대 500파일·합계 100MB로 제한한다. 전체 행 검증을 생략하거나 일부 표본만으로 적용하지 않는다. 이 상한에서의 성능 부하 검증을 수행했다는 의미는 아니다.

## I단계 이후 변경

복원 적용 후 검색 갱신은 [영속 작업 큐](SEARCH_INDEX_JOBS.md)로 자동 처리한다. 적용 응답은 `index_status=queued`이며 장부 관리의 검색 갱신 상태에서 완료·재시도를 확인한다. 위 H 수용 기록의 `updated`는 당시 동기 처리의 기록이다.
