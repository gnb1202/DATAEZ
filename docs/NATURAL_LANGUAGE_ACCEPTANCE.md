# N: 자연어 50문항 통합 평가

2026-09-08. 자연어 요청에서 출처 선택, 검증된 지표 정의, SQL 결과, 그래프, 대시보드 변경까지 평가했다. 실제 PG 파일 대신 합성 자료를 사용했다.

마지막 수정은 관련 10문항으로 검증했다. 50문항 전체의 측정 성적은 47/50으로 보존하며, 부분 재검증 결과를 합쳐 “전체 50/50”으로 표시하지 않는다. 마지막 코드의 모델·소스 지문은 10문항 보고서에서 확인할 수 있다.

전체 평가에서 외부 소유자 데이터 노출, 원본 거래 변경, 요청하지 않은 대시보드 변경은 0건이다. 올바른 정의를 생성하지 못한 경우도 실패로 포함했다. 모델이 존재하지 않는 장부 ID를 보내 접근 검증에서 거절된 문항을 성공한 빈 데이터 조회로 간주하지 않았다.

최초 준비 실행에는 평가기의 Decimal/날짜 JSON 직렬화 오류가 있었다. 해당 실행은 제품 정확도 성적에서 제외했다. 이후 완전한 실행 근거가 남은 평가부터 비교한다. 올바르게 완료한 명시적 수정에 별도 미리보기 호출이 없다는 이유만으로 실패시키던 검사도 수정했다. 질문이나 정답 금액을 바꾸지 않고 저장된 근거를 재채점했으며 원본과 재채점 이유를 모두 보존했다.

## 평가로 발견하고 보완한 내용

1. **별도 취소의 절댓값 처리**
   - 현금 55,000원에서 취소 7,000원과 -3,000원을 각각 차감해야 한다.
   - 모델이 `ABS(SUM(amount))`를 선택하면 취소 4,000원만 차감해 51,000원이 된다.
   - 개별 취소에 `-ABS`를 적용하는 v2 `amount_mode=refund`와 집계 후 절댓값인 v3/v4 `absolute`를 도구 스키마·프롬프트에서 구분했다. 재평가에서는 45,000원으로 계산했다.
2. **요청하지 않은 누락 제외 조건**
   - 수수료에 `is_not_null`, 채널에 `!= ''`를 자동으로 붙이면 현재 수치는 같아도 나중에 들어온 미제공 값을 조용히 제외한다.
   - 필터 설명과 생성 지침을 보완해 사용자 요청에 없는 숫자·분류 누락 제외를 금지했다. 명시적으로 제공분만 요청한 문항은 계속 허용한다.
3. **여러 가게 합계와 출처 확인**
   - 빈 가게가 있어도 전체 합계를 임의로 가게별 비교로 변경하지 않도록 했다.
   - 현재 가게 컨텍스트에도 실제 `table_id`를 전달한다. 다른 가게 조회 결과만 가진 모델이 현재 가게의 UUID를 추측할 필요를 줄였다.
   - 식별자 오류는 거래가 없는 상태와 구분하고, 선택한 가게의 목록에서 ID를 다시 확인해 재시도하도록 했다. 기존 소유권·가게 범위 검증은 유지한다.
4. **계산값과 설명의 일치**
   - 취소 이벤트 수/승인 이벤트 수를 원거래 주문 취소율로 설명하지 않도록 했다.
   - 원장 전체 행 수, 실제 반환된 표본 행 수, 기간·필터 적용 집계값을 구분하는 정보를 도구 결과에 추가했다.
   - 모델에 전달하는 지표 근거에 없는 월별 승인/취소 건수나 원인을 표본에서 추정하지 않도록 했다.
   - 수수료 미차감은 “수수료 차감 전”이라고 명확하게 표현한다.
5. **자료 부족과 검색 요청**
   - 비용 자료가 없으면 영업이익을 수수료 차감액으로 재정의하거나 임의 장부 합계를 대신 계산하지 않는다.
   - 사용자가 의미 검색을 명시하면 실제 검색 도구를 사용한다. 파일 이력 조회를 의미 검색이라고 부르지 않는다.

이 변경은 모델의 지표 생성·설명과 컨텍스트 제공을 보완한다. 임의 코드를 실행하거나 지표 계산 SQL의 허용 범위를 확장하지 않는다. 모델 생성이 항상 정확하다는 보장은 아니며 새로운 질문으로 재평가해야 한다.

## 검증 방식

50문항은 v1 단일 장부, v2 독립 장부 합산, v3 스칼라 계산식, v4 그룹 계산식, v5 여러 가게 지표를 포함한다. 저장→조건 수정→복원→자동 갱신 중지/재개→저장본을 바꾸지 않는 미리보기는 실제 대화 이력으로 연결했다.

- 합성 CSV를 실제 HTTP API로 반영하고 백그라운드 검색 색인이 완료될 때까지 기다렸다.
- 실제 pgvector·임베딩·모델과 운영 코드의 동기 `run_agent`를 사용했다.
- 정답은 애플리케이션 SQL이나 모델 결과를 사용하지 않는 CSV/Decimal 계산기로 구했다.
- SQL 결과의 정확한 셀과 지표 정의를 별도 비교했다. 숫자가 문자열 어딘가에 포함됐다는 이유로 통과시키지 않는다.
- 전체 도구 실행 기록, 위젯 변경 전후, 원본·가게·업로드·현금 기록의 DB 스냅샷을 확인했다.
- 응답 문장과 실행 근거를 개발 에이전트가 직접 검토했다. 독립적인 사업자 평가단의 평가와는 구분한다.
- 검색 recall@5 보조 질의는 3개이며 각 격리 실행에서 반복했다. 50개 검색 질의의 recall로 보고하지 않는다.

보고서 생성기는 질문 누락/중복, 다른 소스·모델·날짜가 섞인 결과, 미정리 임시 DB, 원시 근거와 다른 결과, 누락되거나 오래된 설명 검토를 거절한다. 초기 목표인 90% 통과와 주요 변경·격리 위반 0건을 각각 판정한다.

검증 결과:
- API 전체 회귀 **696개 통과**, 이후 마지막 컨텍스트·표본 정보 변경 관련 API **125개 재검증 통과**.
- 독립 정답 계산기·채점기·보고서 검증 **25개 통과**. 잘못된 출처·필터·금액, 중복 차원, 무단 변경, 누락/중복 문항, 오래된 검토, 결과 변조를 놓치지 않는지 검사한다.
- 마지막 관련 API/평가 도구 묶음 실행은 149개 통과·skip 0이었으며, 이후 추가한 부분 보고서 구분 검사까지 평가 도구 25개를 다시 통과했다.
- 프론트엔드 변경이나 새로운 브라우저 빌드는 이번 Phase에 포함하지 않았다.

## 모델·지연·비용

모델은 `gpt-5.4`, 라우터는 `gpt-5.4-nano`, 임베딩은 `text-embedding-3-small`을 사용했다. 설정·질문·채점기·소스 지문과 실행일은 보고서에 남긴다.

전체 재평가 50문항의 문항 처리 시간은 p50 **10.718초**, p95 **24.25초**, 최대 **32.094초**였다. 세 격리 실행과 API 회귀 테스트가 함께 동작한 로컬 측정이다. 소형 합성 자료의 동기 에이전트 측정이므로 실제 브라우저 응답 시간, 운영 부하 성능 또는 속도 개선 효과로 해석하지 않는다.

해당 50문항의 토큰은 **1,892,636개**, 저장소 가격표 기반 추정 비용은 **$2.428276**이다. 라우터·분석·문항 내 검색 호출을 포함하고, 초기 자료 색인과 준비/다른 재평가 실행은 제외한다. 실제 청구액이나 이번 개발 전체 비용이 아니다.

마지막 10문항 회귀는 p50 7.468초·p95 12.609초, 383,317토큰·추정 $0.497076였다. 문항 구성과 동시 실행 조건이 달라 전체 50문항보다 빨라졌다는 근거로 사용하지 않는다.

## 재현과 다음 검증

실행 방법과 질문별 범위는 [평가 도구 안내](../scripts/nl-eval/README.md)에 있다. 각 실행은 자신이 만든 loopback 임시 DB·API를 정리하며 Next 빌드나 사용자의 실제 데이터를 변경하지 않는다.

이번 실행의 임시 평가 DB가 남아 있지 않음을 확인했고, 작업용 pgvector 컨테이너와 이번 검증에 시작한 로컬 PostgreSQL을 종료했다. 원시 실행 기록은 git에서 제외한 평가 artifacts 폴더에 보존한다.

이번 Phase는 50문항 전체의 브라우저·스트리밍 평가가 아니다. 이전 J/M의 브라우저 검증과 분리해 읽어야 한다. 실제 사용자 사용성, 장기 갱신·10만 행 부하, 실제 PG 사업자 파일은 이번 결과에 포함하지 않는다.

다음은 처음 사용하는 사람이 샘플 파일에서 첫 대시보드까지 진행하는 사용성 점검이다. 자연어 정확도는 이번 질문을 계속 고치는 평가와 별도로, 보지 않은 질문·다른 파일 구조·부분 취소 관계·미제공 분류가 포함된 자료로 후속 평가한다.
