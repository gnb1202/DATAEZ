# M: 여러 가게 순결제액 합산·비교

2026-09-08. 한 사용자가 선택한 가게들의 결제·취소 장부를 같은 기준으로 계산하고 현재 가게의 대시보드에 저장한다.

## 사용 흐름

- “강남점과 홍대점의 이번 달 순결제액을 가게별 막대그래프로 저장하고 매시간 갱신해줘.”
- “방금 저장한 비교 지표의 기간을 지난달로 바꿔줘. 위치와 갱신 주기는 유지해줘.”
- “강남점과 수원점을 비교하되, 거래가 없는 가게도 데이터 없음으로 남겨줘. 미리보기만 해줘.”

대화에서 소유 가게와 장부를 조회하고 실제 컬럼·표본·출처 설명을 확인한다. 결제 원금, 취소 부호, 통화, 발생일의 의미가 불분명하면 연결 기준을 확인한다. 검색은 가게 ID별로 범위를 한정한다. 기존 단일 가게 조회·수정 도구의 권한 범위는 넓히지 않는다.

대시보드의 **여러 가게 순결제액 비교·합산**에서도 대상 가게, 가게별 장부, 금액·날짜·통화 컬럼, 취소 처리, 공통 기간, 갱신 주기를 지정할 수 있다. 계산 결과를 미리 본 뒤 출처의 의미와 중복 여부를 확인하여 저장한다. 현재 가게에 장부가 없어도 다른 소유 가게를 선택할 수 있다.

저장 위치와 계산 대상을 구분한다. 위젯은 현재 가게 대시보드에 속하고, 계산 대상은 정의에 저장된 가게 ID 목록이다. 나중에 가게를 추가해도 기존 지표에 자동으로 포함되지 않는다.

## 계산 범위

| 항목 | 지원 규칙 |
|---|---|
| 대상 | 본인 소유의 활성 가게 2~10개, 가게당 장부 1~5개, 전체 최대 20개 |
| 금액 | 원화 순결제액. 승인·취소 발생일 기준, 수수료 차감 전 |
| 취소 | 결제·취소 혼합 원장은 원본 부호 유지. 별도 취소 원장은 `-abs(amount)`로 차감 |
| 기간 | 전체·이번 달·지난달·최근 30일 중 하나를 모든 가게에 공통 적용. 한국 시간 기준 |
| 표시 | 선택 가게 전체 합계 KPI 또는 가게별 막대그래프 |
| 갱신 | 수동·매시간·24시간. 저장한 정의를 재실행하며 LLM 호출 없음 |
| 수정 | 기존 수정·이력·복원 API 사용. 위젯 ID·배치·갱신 주기 유지 |

통화 컬럼이 지정되어 있거나 실제 장부에 `currency` 컬럼이 있으면 값이 모두 KRW인지 검사한다. 공백 정리·대문자 변환 후 외화 또는 빈 통화가 있으면 계산을 거절한다. 통화 컬럼이 없는 파일은 사용자가 원화 장부로 지정한 선언을 사용한다. 서로 다른 통화를 환산하지 않는다.

금액 NULL·NaN·무한대, 기간 계산에 필요한 발생일 누락도 계산을 거절한다. 품질 검사는 출처별 필터를 적용한 장부 전체에 수행하므로 선택 기간 밖의 잘못된 행도 수정해야 한다.

선택 기간에 거래가 없는 가게는 비교표에서 삭제하지 않고 `value=null`과 사유를 보존한다. 해당 가게가 있는 전체 합계도 계산 불가로 표시한다. 나머지 가게만 더해 전체 합계로 제시하지 않는다. 실제 거래 합계가 0인 경우는 정상적인 0으로 표시한다.

가게 이름이 같아도 ID별로 별도 집계한다. 장부 ID 또는 같은 원본 파일의 중복 선택은 거절한다. 서로 다른 파일에 중복 기록된 거래, 내부 이체, 결제 원금과 정산 입금액의 혼합은 자동으로 판별·제거하지 않는다. 자연어 안내와 수동 확인에서 출처를 구분해야 한다.

## 지표 정의와 SQL

기존 v1~v4는 유지하고 `version=5`를 추가한다. 아래 UUID는 설명용이며 실제 요청에서는 조회로 확인한 ID를 사용한다.

```json
{
  "version": 5,
  "operation": "sum",
  "basis": "net_payments",
  "date_basis": "payment_refund_occurred_at",
  "group_by": "store",
  "chart_type": "bar",
  "time_range": "this_month",
  "stores": [
    {
      "project_id": "강남점 UUID",
      "sources": [{
        "table_id": "강남점 결제원장 UUID",
        "label": "결제원장",
        "column": "amount",
        "date_column": "occurred_at",
        "currency": "KRW",
        "currency_column": "currency",
        "amount_mode": "signed",
        "filters": []
      }]
    },
    {
      "project_id": "홍대점 UUID",
      "sources": [{
        "table_id": "홍대점 결제원장 UUID",
        "label": "결제원장",
        "column": "amount",
        "date_column": "occurred_at",
        "currency": "KRW",
        "currency_column": "currency",
        "amount_mode": "signed",
        "filters": []
      }]
    }
  ]
}
```

`group_by=none`이면 같은 정의로 전체 합계 KPI를 만든다. 미리보기·생성·갱신·수정은 기존 `/api/projects/{현재 가게}/metrics` API를 사용한다. 자연어용 읽기 도구는 `list_stores`, `list_store_tables`, `inspect_store_table`, `search_store_schema`다. 가게/장부 목록은 다음 페이지 위치를 제공한다.

서버는 저장 위치와 모든 대상 가게의 소유권·활성 상태, 각 장부의 실제 소속·컬럼·타입을 검증한다. 검증부터 실행·저장까지 가게와 장부 메타데이터에 공유 잠금을 유지하고 시간 제한을 적용한다. DB 트랜잭션 안에서 LLM이나 외부 네트워크를 호출하지 않는다.

장부마다 공통 형태로 정규화한 뒤 단일 SQL 스냅샷에서 `UNION ALL`·가게별 집계를 수행한다. 선택 가게 목록과 왼쪽 결합하여 빈 가게도 남긴다. 식별자는 인용하고 가게 ID·이름·필터 값은 별도 매개변수로 전달한다. 원본 행끼리 조인하지 않는다. 금액은 PostgreSQL numeric과 소수 문자열로 보존하며 그래프 좌표만 표시용 근삿값이다.

## 출처·실패 표시

**집계표·SQL**에서 가게별 정확한 금액, 포함 행 수, 연결한 장부·금액·발생일·통화 컬럼, 취소 방식, 필터, 계산 시 확인한 장부 변경 시각, 실행 SQL과 매개변수를 확인한다. 위젯에도 계산 대상 가게와 해당 장부 관리 링크를 표시한다.

출처 변경 시각은 마지막 계산에서 확인한 메타데이터다. 여러 가게의 외부 매출이 실시간으로 반영된다는 의미가 아니다. 파일 업로드·직접 입력 이후의 데이터만 계산할 수 있다.

기존 장부 메타데이터의 변경 시각에 시간대가 없으면 원래 기록값과 “시간대 미제공”을 표시한다. 브라우저 시간대로 임의 해석하지 않는다.

선택 가게나 장부가 삭제되거나 접근 불가 상태가 되면 전체 재계산을 중단한다. 기존 갱신 실패 처리로 마지막 성공 결과와 오류를 함께 보존한다. 출처를 몰래 제외하거나 다른 가게로 대체하지 않는다. 정의 복원은 과거 정의를 현재 데이터로 다시 계산한다.

## 검증 재현

```powershell
$env:DATAEZ_RAG_TEST_DATABASE_URL = 'postgresql://dataez_test@127.0.0.1:55440/postgres?connect_timeout=5'
$env:DATAEZ_TEST_DATABASE_URL = 'postgresql://dataez_test@127.0.0.1:55439/postgres?connect_timeout=5'
python -m pytest api/tests -q
python scripts/store-metrics-eval/run.py
```

평가 스크립트는 루프백 PostgreSQL의 새 격리 DB에 강남·홍대·수원 합성 CSV를 만들고 실제 API·모델·Edge 브라우저로 검증한다. 원시 결과·임시 계정 정보는 Git에서 제외한 `scripts/store-metrics-eval/artifacts/`에만 기록한다. 평가 DB·서버를 정리하고 일반 프론트 빌드를 복원한다.

2026-09-08 검증 결과:

- 전체 API **679개 통과, 건너뜀 0개**(173.94초). 새 여러 가게 SQL·권한·수명주기 검사는 31개이며, 큰 저장 지표 목록의 모델 문맥 검사 1개도 추가했다.
- 도구 의존성 연결 보완 후 관련 에이전트·워크플로 검사 **38개 통과**. TypeScript 검사와 프로덕션 빌드 통과. 기존 ESLint 9 설정 호환 문제는 남아 있어 lint 통과로 보고하지 않는다.
- 실제 `gpt-5.4` / `gpt-5.4-nano`, `text-embedding-3-small`, Edge로 수동 가게 선택과 세 자연어 시나리오를 검증했다. API 모킹 없이 평가의 **13개 확인 항목 통과**, 브라우저 예외 0건이다.
- 강남·홍대 이번 달 순결제액 **80,000원 / 170,000원**, 전체 합계 **250,000원**. 지난달로 수정한 비교는 **60,000원 / 40,000원**이며 ID·크기·배치·매시간 주기를 유지했다.
- 수원점의 이번 달 거래 없음은 비교표에 계산 불가로 남았다. 선택하지 않은 수원점의 과거 **99,999,999원**은 두 가게 합계·비교에 포함되지 않았다.
- 홍대점에 합성 거래를 추가한 뒤 합계가 **300,000원**으로 재계산됐다. 홍대점 삭제 후 재계산은 실패하고 마지막 성공 값 300,000원과 오류를 보존했다.
- 격리 평가 DB·API·웹 프로세스를 정리하고 일반 웹 빌드를 복원했다.

## 남은 범위

여러 가게를 날짜별로 겹쳐 표시하는 차트, 가게별 증감률·임의 중첩 수식, 환율 환산, 정산 입금액 대조, 계정 간 가게 공유는 이번 범위에 포함하지 않는다. 실제 PG 파일 파일럿은 서비스 일정이 정해질 때까지 보류한다. 후속으로 [J의 첫 업로드·매핑·첫 지표 안내](FIRST_DASHBOARD.md)를 구현했다. PRD의 50문항 평가·실사용자 사용성·운영 부하 검증은 남아 있다.
