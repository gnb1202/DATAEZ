# 여러 가게 실제 모델·브라우저 평가

`python scripts/store-metrics-eval/run.py`로 실행한다. 루프백의 pgvector PostgreSQL 관리 DSN을 `DATAEZ_RAG_TEST_DATABASE_URL`로 제공해야 한다. Python API 의존성, `web/node_modules`, `scripts/ui-eval/node_modules`의 Playwright 및 Edge가 필요하다. 모델 API 키는 환경 변수 또는 루트 `.env`에서 읽고 출력하지 않는다.

합성 가게 3개와 CSV로 다음 흐름을 확인한다.

1. 화면에서 강남·홍대를 선택하여 순결제액 합계 250,000원 저장.
2. 실제 모델 대화로 두 가게의 이번 달 막대 비교 저장, SQL·집계표 확인.
3. 크기를 바꾼 뒤 자연어로 지난달로 수정. 위젯 ID·배치·매시간 주기 유지.
4. 이번 달 거래가 없는 수원점을 포함한 비교를 미리보기. 수원점을 제외하거나 0으로 바꾸지 않음.
5. 재접속 후 두 위젯 확인. 다른 선택 가게의 거래 추가 후 합계 300,000원 재계산.
6. 선택 가게 삭제 시 재계산 실패와 마지막 성공 결과 보존.

API 모킹을 사용하지 않는다. 새 임시 DB와 임의 로컬 포트의 서버만 사용하고 종료 시 정리한다. 평가용 Next 빌드도 일반 빌드로 복원한다. 실행 중 다른 작업에서 같은 `web/.next`를 빌드하지 않는다.

`artifacts/`에는 임시 계정 입력과 원시 대화·로그가 있어 Git에서 제외한다. 공개 평가 기록에는 검증 결과, 합성 질문·답변·사용량 및 검토한 화면만 추린다. 실제 PG 파일 검증이나 50문항 벤치마크를 대신하지 않는다.
