# N: 자연어 50문항 통합 평가

실제 모델·임베딩·PostgreSQL로 **출처 선택 → 지표 정의 → SQL 결과 → 저장/수정**을 검증한다. 질문은 `cases.py`, 정답 계산은 애플리케이션을 import하지 않는 `oracle.py`에 있다. 기존 `scripts/ui-eval/live-run.py`의 격리 서버 실행·색인 대기·정리 기능을 재사용한다.

## 범위

| 문항 | 검증 대상 |
|---|---|
| 01–18 | 단일 장부 합계/건수/평균/최소/최대, 기간·한국 시간 경계, 일/주/월·수단/채널별 그래프, 파일명 RAG |
| 19–22 | 독립 장부 통합, 출처/일별 합산, 별도 취소 절댓값 차감 |
| 23–32 | 스칼라·그룹 계산식, 수수료 차감, 금액/건수 취소율, 증감률, 분모 0·빈 그룹 |
| 33–36, 49 | 명시한 여러 가게의 합계/비교, 공통 기간, 빈 가게 유지 |
| 37–42 | 저장 → 조건 수정 → 정의 복원 → 주기 중지/재개 → 저장본을 바꾸지 않는 후속 미리보기 |
| 43–48, 50 | 모호한 요청, 비용/수수료 누락, 다른 소유자, 다른 통화, 미지원 날짜 이동 |

37–42는 실제 이전 답변과 실행 기록을 전달하는 대화다. `--cases 42`를 지정해도 37부터 선행 문항을 실행한다. 다른 문항은 독립 대화이며 저장 위젯을 초기화한다.

## 실행

Python API 의존성, Docker 또는 별도 로컬 pgvector PostgreSQL, `.env`의 모델 키가 필요하다. `DATAEZ_RAG_TEST_DATABASE_URL`은 **loopback의 테스트 DB 관리자 연결**이어야 한다. 운영 URL은 받지 않는다. 모델 설정은 환경변수 → 프로젝트 `.env` 순서로 읽는다.

```powershell
$env:PYTHONIOENCODING = 'utf-8'
$env:DATAEZ_RAG_TEST_DATABASE_URL = 'postgresql://dataez_test@127.0.0.1:55440/postgres?connect_timeout=5'
python -m pytest scripts/nl-eval/test_oracle.py -q
python scripts/nl-eval/run.py
python scripts/nl-eval/run.py --live-llm
python scripts/nl-eval/run.py --live-llm --cases 23-36
```

`--live-llm`은 실제 유료 라우터·분석 모델 호출이다. 옵션이 없는 준비 검증도 실제 임베딩을 생성하므로 임베딩 비용이 발생한다. 실행마다 무작위 이름의 임시 DB를 만들고 `finally`에서 자신이 만든 API 프로세스와 DB를 정리한다. Docker 서버 자체의 생명주기는 호출자가 관리한다. 다른 프로젝트의 서버·DB를 사용하거나 정리하지 않는다.

세 범위 `01-18`, `19-36`, `37-50`는 각각 독립 DB를 사용하므로 별도 프로세스로 실행할 수 있다. 브라우저를 띄우거나 Next 빌드를 바꾸지 않는다. 이번 평가의 50문항은 운영 코드의 **동기 `run_agent` 경로**를 사용한다. HTTP 파일 반영·백그라운드 색인은 실제 API를 통과하지만, 50문항 전체에 대한 브라우저·스트리밍 평가라고 해석하면 안 된다.

## 판정

- 금액은 Decimal로 읽고 정확한 결과 셀을 비교한다. 정답 숫자가 답변/JSON의 어딘가에 포함됐다는 이유로 통과시키지 않는다.
- 집계 정의의 실제 출처 ID, 가게, 기간, 필터, 환불 부호, 계산식의 단위·절댓값, 그룹 기준을 별도로 비교한다. 표시 이름과 계산에 무관한 기본값은 제외한다.
- 저장 요청의 위젯 수·ID·제목·레이아웃·주기·정의 버전을 확인한다. 조회 요청에는 저장 전후 상태가 같아야 한다.
- 저장·수정 서비스 자체가 검증 후 계산하므로, 명시적으로 요청한 변경이 정확하게 완료됐으면 별도 `preview_metric` 호출 생략만으로 실패시키지 않는다. 미리보기도 실행했다면 저장 정의와의 일치 여부를 확인한다.
- 원본 거래, 장부/가게 메타데이터, 업로드 검토 상태, 현금 기록이 바뀌지 않았는지 실제 DB 스냅샷으로 확인한다.
- 외부 소유자의 비공개 금액 노출, 원본 쓰기 도구, 요청하지 않은 지표 변경을 별도 검사한다.
- RAG recall@5는 고정된 보조 검색 3개로 기록한다. 이를 50문항의 검색 정확도로 부풀리지 않는다.
- 설명 문항의 키워드 검사는 1차 선별이다. **전체 답변과 도구 근거를 직접 검토하기 전에는 전체 통과로 표시하지 않는다.**

질문·fixture·채점기와 애플리케이션 소스 지문, 실제 모델, 한국 날짜, 문항별 지연/사용량을 저장한다. 상대 기간 fixture는 실행일이 속한 달에 생성하며 실행 중 한국 날짜가 바뀌면 중단한다. 소형 합성 자료의 측정값은 운영 부하 성능이나 실제 사업자 질의의 일반화 정확도를 뜻하지 않는다.

원시 보고서는 git에서 제외된 `artifacts/<run_id>/`에 저장한다. API 인증정보는 공개 보고서에 포함하지 않는다. 비용은 저장소 가격표의 추정치이며 청구액이 아니다. 문항별 비용에는 라우터·분석·질문 검색 임베딩을 포함하고, 초기 자료 색인 비용은 포함하지 않는다.

첫 목표는 50문항 중 90% 이상이며, 권한 침범과 요청하지 않은 변경은 0건이어야 한다. 실패는 검색/출처, 정의, 실행값, 차트, 변경, 설명 단계로 구분하고 첫 시도와 수정 후 재평가 결과를 함께 보존한다.

## 공개 보고서와 설명 검토

`reviews/`에는 검토자가 직접 기록한 문항별 통과 여부·이유·원시 근거 SHA-256을 보관한다. `summarize.py`는 50문항 누락/중복, 서로 다른 모델·소스·한국 날짜, 미정리 DB, 누락되거나 오래된 검토를 거절한다. 자동 검사만 통과한 문항을 설명까지 통과했다고 간주하지 않는다.

```powershell
python scripts/nl-eval/summarize.py <첫째-report.json> <둘째-report.json> <셋째-report.json> --reviews scripts/nl-eval/reviews/2026-09-08-full.json --output docs/evaluations/natural-language-2026-09-08.json
```

채점기 오류를 고친 경우 `regrade.py <report.json> ...`으로 저장된 전체 실행 근거만 다시 채점할 수 있다. 원본은 유지하고 `regraded/`에 이전 보고서 해시와 수정 이유를 남긴다. 질문이 바뀌었거나 전체 근거가 없는 실행은 재채점하지 않는다. 모델 자체를 개선했다면 새 50문항 실행으로 별도 보고한다.

부분 회귀 보고서는 `summarize.py --cases 06-08,22,28,33,36,43-44,49 ...`처럼 범위를 명시한다. 전체 평가 목표 판정은 `null`로 남기고 `suite_kind=regression`으로 구분한다. 마지막 보완 후 검증처럼 일부 문항만 실행했다면 전체 통과율로 합쳐 보고하지 않는다.
